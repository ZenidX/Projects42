C Piscine — C 08

El módulo del preprocesador. Aquí no se escriben apenas funciones: se escriben cabeceras (.h). Se aprende para qué existe el #include, qué es una macro, cómo se declara un struct y cómo se agrupan datos en memoria. 6 ejercicios (ex00–ex05).

  • ex00 — ft.h
  • ex01 — ft_boolean.h
  • ex02 — ft_abs.h
  • ex03 — ft_point.h
  • ex04 — ft_strs_to_tab
  • ex05 — ft_show_tab
El preámbulo — El enunciado abre con la entrada de Wikipedia sobre el ornitorrinco: un mamífero que pone huevos, con pico de pato y espolón venenoso, que los naturalistas europeos tomaron por una broma. Cierra con el clásico de la casa: "este enunciado no tiene nada que ver con el ornitorrinco". El guiño encaja con el módulo: la cabecera es esa pieza rara que no es del todo código ejecutable ni del todo documentación.

ex00ft.h

Entregable: ft.hFunciones autorizadas: ninguna

Crear un archivo de cabecera con los prototipos de cinco funciones:

#ifndef FT_H
# define FT_H

void	ft_putchar(char c);
void	ft_swap(int *a, int *b);
void	ft_putstr(char *str);
int	ft_strlen(char *str);
int	ft_strcmp(char *s1, char *s2);

#endif
Por qué existen los .h — El compilador de C procesa cada .c por separado y no sabe nada de las funciones que viven en otro archivo. Un prototipo es una promesa: "esta función existe, se llama así y tiene estos tipos". El #include "ft.h" no es magia — el preprocesador literalmente pega el contenido del .h en el punto del #include antes de compilar. Por eso una cabecera solo debe declarar, no definir: si dos .c incluyen el mismo .h con código dentro, ese código se duplica y el enlazador se queja. El #ifndef FT_H / #define FT_H / #endif es el include guard: si un mismo archivo se incluye dos veces (algo habitual con cabeceras que se incluyen entre sí), la segunda vez la macro FT_H ya está definida y todo el bloque se salta. Sin él, redefiniciones y errores. La Norma exige el guard con el nombre del archivo en mayúsculas.

ex01ft_boolean.h

Entregable: ft_boolean.hNorminette: -R CheckDefine

El enunciado da un main ya escrito y hay que crear la cabecera que lo haga compilar y funcionar: cuenta si el número de argumentos es par o impar.

# include <unistd.h>

# define EVEN_MSG "I have an even number of arguments.\n"
# define ODD_MSG "I have an odd number of arguments.\n"
# define SUCCESS 0
# define TRUE 1
# define FALSE 0
# define EVEN(nbr) ((nbr) % 2 == 0)

typedef int	t_bool;

La cabecera aporta todo lo que el main usa sin definir: el tipo t_bool (un simple int con nombre con intención), las constantes TRUE/FALSE/SUCCESS, los mensajes y la macro EVEN. Incluye <unistd.h> porque el main llama a write sin incluirlo él mismo.

Macros y typedef — Una macro #define es sustitución de texto pura, antes de compilar: donde ponga EVEN(x) el preprocesador escribe ((x) % 2 == 0). No es una función: no hay llamada, no hay tipos, no hay coste en tiempo de ejecución. El typedef int t_bool no crea un tipo nuevo, solo un alias: sirve para que el código se lea con intención (t_bool dice "esto es un sí/no", aunque por dentro sea un entero). El flag -R CheckDefine hace que la norminette vigile expresamente el estilo de las macros: constantes en mayúsculas y bien formadas.

ex02ft_abs.h

Entregable: ft_abs.hNorminette: -R CheckDefine

Una sola macro que sustituye su parámetro por su valor absoluto:

# define ABS(Value) (((Value) < 0) ? -(Value) : (Value))
Los paréntesis no son decorado — En una macro, cada aparición del parámetro tiene que ir entre paréntesis, y el resultado entero también. Como la macro es sustitución de texto, ABS(a - b) sin paréntesis se expandiría a -a - b (que no es -(a-b)) y romper la precedencia. Con -(Value) y el paréntesis exterior, la expansión respeta el operando completo. Es el peligro clásico de las macros frente a las funciones: no evalúan argumentos, copian texto. Por eso también ABS(x++) incrementaría x dos veces — una macro no es una función, aunque lo parezca.

ex03ft_point.h

Entregable: ft_point.h

Una cabecera que declare un tipo t_point con dos enteros, de modo que compile el main del enunciado (que hace point->x = 42; point->y = 21;).

typedef struct s_point
{
	int	x;
	int	y;
}	t_point;
Structs: agrupar datos en memoria — Un struct es un molde para poner varias variables juntas bajo un mismo nombre, contiguas en memoria. Aquí un t_point ocupa dos int seguidos; point.x es el primero y point.y el siguiente. El detalle de estilo 42: la estructura se llama s_point y el alias t_point (prefijos s_ de struct y t_ de type). El -> del main es azúcar para "desreferencia el puntero y accede al campo": point->x es (*point).x. Entender que un struct es solo memoria contigua es la base de todo lo que viene después: arrays de structs, listas enlazadas, y la gestión manual de memoria.

ex04ft_strs_to_tab

Entregable: ft_strs_to_tab.cFunciones: malloc, free

Transformar un array de cadenas (los argumentos) en un array de estructuras t_stock_str, cada una con el tamaño de la cadena, la cadena original y una copia:

typedef struct s_stock_str
{
	int		size;
	char	*str;
	char	*copy;
}	t_stock_str;

Se reserva memoria para ac + 1 estructuras; la última hace de centinela con str = 0 para marcar el final. La copia se hace con un ft_strdup propio (reservar len + 1 y copiar carácter a carácter). Si algún malloc falla, se devuelve NULL.

Array de structs y el centinela — Aquí se juntan dos ideas: reservar memoria dinámica (malloc) para un número de elementos que no se sabe hasta ejecución, y usar un valor centinela para marcar el final en vez de llevar la cuenta aparte (el mismo patrón que el '\0' al final de las cadenas, o el NULL al final de argv). Reservar ac + 1 y dejar la última con str = 0 permite recorrer el array sin conocer su longitud. La copia existe para que el ejercicio siguiente pueda modificarla sin tocar el original: el struct guarda el dato y una versión de trabajo.

ex05ft_show_tab

Entregable: ft_show_tab.cFunciones: write

Recorrer el array creado por el ejercicio anterior y mostrar, por cada estructura: la cadena, su tamaño y la copia, cada uno seguido de un salto de línea.

while (par[i].str)
{
	ft_putstr(par[i].str);
	write(1, "\n", 1);
	ft_putnbr(par[i].size);
	write(1, "\n", 1);
	ft_putstr(par[i].copy);
	write(1, "\n", 1);
	i++;
}
Recorrer hasta el centinela — El bucle no necesita saber cuántos elementos hay: avanza mientras par[i].str no sea NULL, que es justo la marca de fin que dejó ft_strs_to_tab. Este par de ejercicios (ex04 construye, ex05 consume) es el primer contacto con el patrón productor/consumidor sobre una estructura de datos propia, y con el hecho de que solo se dispone de write: no hay printf, así que hay que escribir a mano un ft_putnbr para imprimir el tamaño dígito a dígito.
