C Piscine — C 01

El módulo de punteros: nueve ejercicios para interiorizar que en C todo es memoria con dirección, y que un puntero no es más (ni menos) que esa dirección guardada en una variable.

  • ex00 — ft_ft
  • ex01 — ft_ultimate_ft
  • ex02 — ft_swap
  • ex03 — ft_div_mod
  • ex04 — ft_ultimate_div_mod
  • ex05 — ft_putstr
  • ex06 — ft_strlen
  • ex07 — ft_rev_int_tab
  • ex08 — ft_sort_int_tab
Por qué un módulo entero de punteros — C pasa todo por valor: cuando llamas f(x), la función recibe una copia y no puede tocar tu variable. La única forma de que una función modifique algo del que llama es darle la dirección de ese algo. De esa limitación — deliberada, C es de 1972 y mapea casi directo a ensamblador — nace todo este módulo: los punteros no son un tema avanzado de C, son el mecanismo del lenguaje para compartir memoria entre funciones. (El prólogo del enunciado atribuye a "Una noche en la ópera de los Hermanos Marx" el diálogo de la Royale con queso… que es de Pulp Fiction. Error a propósito: comprobar las fuentes también es parte del oficio.)

ex00ft_ft

Entrega: ft_ft.cAutorizado: nada
void	ft_ft(int *nbr)
{
	*nbr = 42;
}
Qué te obliga a aprender — La pareja de operadores que define C: & ("dame la dirección de") y * ("ve a esta dirección"). Escribir *nbr = 42 es: toma la dirección que te han pasado, ve a esa celda de memoria y escribe 42 en ella. El que llama ve su variable cambiada sin que se la hayas "devuelto". Una línea de código, pero es el modelo mental completo de la indirección.

ex01ft_ultimate_ft

Entrega: ft_ultimate_ft.cAutorizado: nada
void	ft_ultimate_ft(int *********nbr)
{
	*********nbr = 42;
}
Qué te obliga a aprender — Nadie usa nueve niveles de indirección; el absurdo es el mensaje. Cada * del tipo añade un salto ("puntero a puntero a…"), y cada * al usarlo deshace exactamente uno. Si entiendes que *********nbr son nueve saltos encadenados hasta llegar al int del fondo — y que el main de prueba necesita nueve variables intermedias, cada una guardando la dirección de la anterior — los dobles punteros de C12 (t_list **) te parecerán triviales. Es vacunación por sobredosis.

ex02ft_swap

Entrega: ft_swap.cAutorizado: nada
void	ft_swap(int *a, int *b)
{
	int	tmp;

	tmp = *a;
	*a = *b;
	*b = tmp;
}
Qué te obliga a aprender — El ejercicio canónico de "por qué existen los punteros": un swap por valor (void swap(int a, int b)) compila, corre y no hace nada visible — intercambia las copias. Solo con direcciones el efecto sobrevive al return. También introduce el patrón de la variable temporal: no puedes pisar un valor sin guardarlo antes. Este swap reaparecerá dentro de rev_int_tab, sort_int_tab y todos los sorts que escribas.

ex03ft_div_mod

Entrega: ft_div_mod.cAutorizado: nada
void	ft_div_mod(int a, int b, int *div, int *mod)
{
	*div = a / b;
	*mod = a % b;
}
Qué te obliga a aprender — C solo puede devolver UN valor con return. ¿Y si una operación produce dos (cociente y resto)? El idioma clásico: parámetros de salida — el llamador reserva las variables y te pasa sus direcciones para que las rellenes. Así funcionan media libc y todas las APIs de sistema (pipe(int fd[2]), waitpid(&status)…). Los lenguajes modernos devuelven tuplas; C te enseña qué hay debajo de esa azúcar.

ex04ft_ultimate_div_mod

Entrega: ft_ultimate_div_mod.cAutorizado: nada
void	ft_ultimate_div_mod(int *a, int *b)
{
	int	div;
	int	mod;

	div = *a / *b;
	mod = *a % *b;
	*a = div;
	*b = mod;
}
Qué te obliga a aprender — Ahora los punteros son entrada y salida a la vez, y aparece un peligro nuevo: el orden. Si escribes *a = *a / *b y después calculas el resto, ya has destruido el valor original de *a — el resto saldrá mal. Hay que leer todo antes de escribir nada (de ahí las temporales). Es la primera lección de aliasing: cuando lees y escribes a través de punteros, el orden de las operaciones es parte de la corrección.

ex05ft_putstr

Entrega: ft_putstr.cAutorizado: write
void	ft_putstr(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		write(1, &str[i], 1);
		i++;
	}
}
Qué te obliga a aprender — Que en C no hay tipo cadena. Una "string" es solo la dirección de su primer carácter, y la convención de que termina donde aparezca el byte 0 ('\0'). La condición while (str[i]) es literalmente "mientras el byte no sea cero". De esa decisión de diseño de 1972 — comprometida pero baratísima en memoria — salen strlen, los buffer overflows, y medio siglo de bugs; conviene entenderla bien porque es la base de los módulos C02-C04 y de C07.

ex06ft_strlen

Entrega: ft_strlen.cAutorizado: nada
int	ft_strlen(char *str)
{
	int	i;

	i = 0;
	while (str[i])
		i++;
	return (i);
}
Qué te obliga a aprender — La consecuencia directa del diseño de ex05: como la longitud no se guarda en ninguna parte, medirla cuesta recorrer la cadena entera, O(n). En lenguajes con la longitud almacenada, len() es O(1). Entender este coste explica patrones de todo el C real: por qué no se llama strlen dentro de la condición de un bucle, por qué las APIs pasan la longitud junto al puntero, por qué existen strlcpy/strlcat. Primer ejercicio del módulo que devuelve algo: `return (i);`.

ex07ft_rev_int_tab

Entrega: ft_rev_int_tab.cAutorizado: nada
void	ft_rev_int_tab(int *tab, int size)
{
	int	i;
	int	tmp;

	i = 0;
	while (i < size / 2)
	{
		tmp = tab[i];
		tab[i] = tab[size - 1 - i];
		tab[size - 1 - i] = tmp;
		i++;
	}
}
Qué te obliga a aprender — Dos cosas. (1) Un array que entra en una función degenera a puntero: dentro solo tienes la dirección del primer elemento, y por eso el tamaño viaja como parámetro aparte — C no lo sabe. Perder el tamaño = leer memoria ajena. (2) El patrón de los dos índices que avanzan desde los extremos (i y size-1-i) intercambiando — parar en size/2 para no des-invertir, y comprobar que el elemento central impar se queda quieto solo. Invertir in place, sin array auxiliar, es la primera vez que piensas en memoria constante.

ex08ft_sort_int_tab

Entrega: ft_sort_int_tab.cAutorizado: nada
void	ft_sort_int_tab(int *tab, int size)
{
	int	i;
	int	tmp;

	i = 0;
	while (i < size - 1)
	{
		if (tab[i] > tab[i + 1])
		{
			tmp = tab[i];
			tab[i] = tab[i + 1];
			tab[i + 1] = tmp;
			i = 0;
		}
		else
			i++;
	}
}
Qué te obliga a aprender — Tu primer algoritmo de verdad: no hay receta en el enunciado, solo "ordena". La solución de arriba (gnome sort) cabe en la Norma y se razona con un invariante simple: si encuentro un par desordenado, lo arreglo y vuelvo a empezar; si llego al final, está ordenado. Es O(n²) — y está bien que lo sea: la piscine quiere que primero escribas un sort correcto y después, cuando ordenar 100.000 elementos duela, tengas motivo para aprender quicksort. También es el cierre del módulo: swap (ex02) + recorrido con índices (ex07) + mutación in place = ordenación.
