Cursus — get_next_line

Una función, char *get_next_line(int fd), que cada vez que la llamas devuelve la siguiente línea de un descriptor. Sin libft, sin lseek, sin variables globales y leyendo de BUFFER_SIZE en BUFFER_SIZE bytes. El proyecto que enseña las variables static y que castiga cualquier descuido con la memoria.

El problema de fondo — read(fd, buf, n) no sabe nada de líneas: devuelve hasta n bytes, los que haya, y le da igual dónde caigan los '\n'. Un solo read puede traer media línea, o una línea y media, o diez líneas. Así que lo que sobre después del '\n' no se puede tirar: hay que guardarlo para la siguiente llamada. Y como la función se llama una vez por línea y entre llamada y llamada sus variables locales desaparecen, el enunciado da la pista: «un buen comienzo sería saber qué es una variable estática». Además pide leer lo menos posible: nada de cargar el fichero entero y luego trocearlo. Es la versión hecha a mano de lo que hacen fgets o getline en la libc, y la usarás en casi todos los proyectos que lean ficheros.

staticLa memoria entre llamadas

Entrega: get_next_line.c, get_next_line_utils.c, get_next_line.hAutorizado: read, malloc, free
char	*get_next_line(int fd)
{
	static char	*buf[MAX_FD];
	char		*p;
	char		*r;

	if (fd < 0 || fd >= MAX_FD || BUFFER_SIZE <= 0 || !gnl_set_buffer(buf, fd))
		return (NULL);
	r = NULL;
	p = gnl_strchr(buf[fd], CHAR_SEP);
	if (!p)
		r = gnl_read(buf[fd], fd);
	else
		r = gnl_split(buf[fd], p, r);
	if (!r || r[0] == '\0')
	{
		free(r);
		free(buf[fd]);
		buf[fd] = NULL;
		return (NULL);
	}
	return (r);
}

Una variable local normal vive en la pila y muere al salir de la función. Una static declarada dentro de la función vive lo que dura el programa: se inicializa una sola vez (a cero, si no le das valor) y conserva su contenido de una llamada a la siguiente. Pero solo es visible dentro de get_next_line, así que no es una variable global y cumple la prohibición del enunciado.

Aquí la static es un array de punteros, uno por descriptor: buf[fd] es el «resto» pendiente de ese fd. Empiezan todos a NULL, y el primer uso de cada fd reserva su buffer:

void	*gnl_set_buffer(char **buf, int fd)
{
	if (!buf[fd])
	{
		buf[fd] = (char *)malloc(sizeof(char) * (BUFFER_SIZE + 1));
		if (!buf[fd])
			return (NULL);
		buf[fd][0] = '\0';
		buf[fd][BUFFER_SIZE] = '\0';
	}
	return (buf[fd]);
}

La lógica de la función principal tiene dos ramas: si el resto guardado ya contiene un salto de línea, no hace falta leer nada — basta con cortar (gnl_split). Si no, hay que leer más (gnl_read).

Ojo: las funciones auxiliares de get_next_line.c (gnl_split, gnl_read_loop, gnl_read, gnl_set_buffer) no están declaradas static ni en el header, así que son visibles desde fuera del fichero. Funciona igual; solo significa que ocupan esos nombres en el programa que enlace con ellas.

Qué te obliga a aprender — La diferencia entre ámbito (quién puede ver una variable) y duración (cuánto tiempo existe). Una local tiene ámbito de función y duración de una llamada; una global, ámbito de todo el programa y duración de todo el programa; una static local combina ámbito de función con duración de programa. Vive en el segmento de datos (.bss, por estar a cero), no en la pila, y por eso sobrevive. Es la forma que tiene C de darle «memoria» a una función sin exponer ese estado al resto del código.

-DBUFFER_SIZE y el preprocesador

Entrega: get_next_line.hCompilación: cc -Wall -Werror -Wextra -D BUFFER_SIZE=42 <archivos>.c
# ifndef BUFFER_SIZE
#  define BUFFER_SIZE 42
# endif

# ifndef MAX_FD
#  define MAX_FD 1024
# endif

# ifndef CHAR_SEP
#  define CHAR_SEP '\n'
# endif

-D BUFFER_SIZE=42 equivale a poner #define BUFFER_SIZE 42 al principio de cada fichero compilado. El evaluador y la Moulinette lo cambian para probar tu función con 1, con 9999, con 10000000. El #ifndef da un valor por defecto para que el proyecto compile también sin la flag, como exige el enunciado, sin pisar el valor si viene de fuera.

El usuario usa el mismo patrón para dos macros más: MAX_FD, el tamaño del array de buffers, y CHAR_SEP, el carácter que corta las líneas. Esta última es una rareza simpática: compilando con -D CHAR_SEP="' '" la función devolvería palabras en vez de líneas. Ojo con MAX_FD: un fd mayor o igual que 1024 devuelve NULL aunque esté abierto; en Linux el límite de descriptores por proceso puede ser mayor (ulimit -n).

La comprobación BUFFER_SIZE <= 0 al principio de get_next_line cubre a quien compile con -D BUFFER_SIZE=0 o negativo: se devuelve NULL antes de reservar nada. Y como el buffer se reserva con malloc en el heap, un BUFFER_SIZE de 10000000 no revienta la pila, que es lo que pasaría con un char buf[BUFFER_SIZE] local.

Qué te obliga a aprender — Que el preprocesador actúa antes que el compilador y que se le puede hablar desde la línea de órdenes. Y responde a la pregunta del enunciado («¿funciona si es 1? ¿y 10000000? ¿sabes por qué?»): con 1, la función tiene que ser correcta cuando cada read trae un solo byte, y será lenta; con 10000000, tiene que tolerar un buffer enorme, que en la pila no cabría. El tamaño del buffer no debe cambiar el resultado, solo el número de lecturas.

readLeer, acumular, cortar, guardar

Entrega: get_next_line.cAutorizado: read, malloc, free

Cuando el resto no tiene '\n', gnl_read lo copia a la línea en construcción r, vacía el buffer y empieza a leer:

char	*gnl_read(char *buf, int fd)
{
	char	*r;

	r = gnl_strdup(buf, BUFFER_SIZE + 1);
	if (!r)
		return (NULL);
	buf[0] = '\0';
	r = gnl_read_loop(buf, fd, r, read(fd, buf, BUFFER_SIZE));
	return (r);
}

char	*gnl_read_loop(char *buf, int fd, char *r, ssize_t bytes_read)
{
	char	*p;

	while (r && bytes_read > 0)
	{
		buf[bytes_read] = '\0';
		p = gnl_strchr(buf, CHAR_SEP);
		if (p)
		{
			r = gnl_split(buf, p, r);
			break ;
		}
		else
		{
			r = gnl_strncat(r, buf, gnl_strlen(r) + bytes_read);
			buf[0] = '\0';
			bytes_read = read(fd, buf, BUFFER_SIZE);
		}
	}
	if (bytes_read < 0)
	{
		free(r);
		return (NULL);
	}
	return (r);
}

Cada vuelta: read no pone '\0', así que se añade a mano en buf[bytes_read] (para eso el buffer mide BUFFER_SIZE + 1). Si en lo leído no hay salto, todo se acumula en r y se lee otra vez. Si lo hay, se corta:

char	*gnl_split(char *buf, char *p, char *r)
{
	char	*q;

	if (!r)
	{
		r = gnl_strdup("", 0);
		if (!r)
			return (NULL);
	}
	q = gnl_strdup(p + 1, gnl_strlen(p));
	if (!q)
	{
		free(r);
		return (NULL);
	}
	r = gnl_strncat(r, buf, gnl_strlen(r) + (p - buf + 1));
	gnl_strncpy(buf, q, BUFFER_SIZE + 1);
	free(q);
	return (r);
}

p apunta al '\n' dentro de buf. Lo que va después (p + 1) se copia aparte en q; a r se le añaden los p - buf + 1 primeros bytes (la línea con su '\n'), y luego q se vuelve a copiar al principio de buf: ese es el resto que se guarda para la próxima llamada. La copia intermedia en q evita copiar el buffer sobre sí mismo.

El estado entre llamadas, con un fichero "hola\nmundo\nfin" (sin salto final) y BUFFER_SIZE=8:

-------   -----------------   -------------------   ----------   ----------------
   1      ""   (recién         "hola\nmun"  (8)     "hola\n"     "mun"
                malloc)

Qué te obliga a aprender — A pensar en flujos en lugar de en ficheros completos: los datos llegan a trozos de tamaño arbitrario y la frontera lógica (el '\n') casi nunca coincide con la física (el final del read). La solución es siempre la misma tríada — un buffer de lectura, un acumulador y un resto — y la volverás a ver en cualquier código que lea de un socket, de una tubería o de un parser. También obliga a manejar aritmética de punteros con soltura: p - buf es una distancia en bytes, no una dirección.

EOFEl final del fichero y la última línea

Entrega: get_next_line.cValor devuelto: la línea leída, o NULL al terminar o si hay error

read devuelve 0 en fin de fichero y -1 en error. El bucle de lectura para con cualquiera de los dos (bytes_read > 0), pero los distingue después:

  • EOF con algo acumulado (llamada 3 del diagrama): se devuelve r tal cual, sin '\n'. Es lo que pide el enunciado: la línea termina en \n «excepto si se ha llegado al final del archivo y éste no termina con un \n».
  • EOF sin nada (llamada 4): r es la cadena vacía "". get_next_line lo detecta con r[0] == '\0', libera la cadena y también el buffer del fd, pone buf[fd] = NULL y devuelve NULL.
  • Error de lectura: gnl_read_loop libera r y devuelve NULL, y get_next_line libera el buffer por el mismo camino. Lo mismo pasa con un fd que no está abierto: se reserva su buffer, read falla y se libera enseguida.

Que el buffer quede a NULL al terminar tiene una consecuencia práctica: si después se reutiliza ese número de fd para otro fichero, empieza limpio.

Qué te obliga a aprender — Que NULL y "" son cosas distintas (un puntero que no apunta a nada frente a una cadena válida de longitud cero) y que aquí la cadena vacía funciona como señal interna de «no queda nada». Y que una función que devuelve NULL «al terminar» tiene que dejar su estado recogido en ese momento: la última llamada es la que libera.

utilsLas funciones de cadena propias

Entrega: get_next_line_utils.cProhibido: libft

Como la libft está prohibida, el usuario reescribe en get_next_line_utils.c las cinco funciones de cadena que necesita, con prefijo gnl_: gnl_strlen, gnl_strchr, gnl_strdup, gnl_strncpy y gnl_strncat. No son clones de las de la libc: están adaptadas al proyecto. Por ejemplo, gnl_strlen acepta NULL y devuelve 0, y gnl_strdup recibe una longitud máxima y rellena con '\0' hasta el final. La más importante es gnl_strncat, porque no concatena en el sitio sino que reserva una cadena nueva:

char	*gnl_strncat(char *dst, char *src, size_t n)
{
	char	*r;
	size_t	l_d;
	size_t	l_s;
	size_t	i;

	l_d = gnl_strlen(dst);
	l_s = gnl_strlen(src);
	r = gnl_strdup(dst, n);
	free(dst);
	if (!r)
		return (NULL);
	i = 0;
	while (i < l_s && i + l_d < n && src[i])
	{
		r[l_d + i] = src[i];
		i++;
	}
	r[l_d + i] = '\0';
	return (r);
}

n es la longitud total del resultado: por eso las llamadas le pasan gnl_strlen(r) + bytes_read o gnl_strlen(r) + (p - buf + 1). La función copia dst en un bloque de n + 1 bytes, libera dst y añade src detrás.

Qué te obliga a aprender — A diseñar el contrato de propiedad de cada función: gnl_strncat «se come» su primer argumento, y quien la llama tiene que sustituir su puntero por el devuelto (r = gnl_strncat(r, ...)) y no volver a tocar el antiguo. Si la reserva falla, el original ya está liberado y se devuelve NULL, de modo que el error sube sin dejar nada colgando. Es la misma idea que realloc, escrita a mano.

valgrindMemoria y leaks

Requisito: toda la memoria del heap liberada, sin leaksComprobación: valgrind --leak-check=full

El reparto de responsabilidades es este:

  • La línea devuelta es de quien llama: él hace el free.
  • El buffer de cada fd es de get_next_line: se reserva en el primer uso y se libera al llegar a EOF o al fallar.
  • Cada malloc intermedio (q en gnl_split, las copias de gnl_strncat) se libera en la misma función o pasa la propiedad a quien la llama.

Leyendo dos ficheros alternados hasta el final, con BUFFER_SIZE de 1, 3, 42 y 10000000, valgrind no informa de ningún leak.

Dos cosas que conviene saber explicar en la evaluación. Primera: si el programa deja de leer un fd antes de llegar a EOF, su buffer sigue reservado en el array static al terminar el programa. Valgrind lo muestra como still reachable (sigue habiendo un puntero a él), no como definitely lost; con la interfaz que fija el enunciado no hay forma de avisar a la función de que ya no vas a leer más. Segunda: ojo con el coste. Cada vuelta sin salto de línea hace un gnl_strncat que vuelve a copiar toda la línea acumulada, así que una línea de L bytes cuesta del orden de L² / BUFFER_SIZE copias. Con BUFFER_SIZE=1 y líneas muy largas se nota.

Qué te obliga a aprender — Que la memoria dinámica tiene dueño, y que cada puntero que sale de una función tiene que llevar escrito (aunque sea en tu cabeza) quién lo libera. Que un leak no se ve funcionando, solo con herramientas como valgrind. Y la diferencia entre «memoria perdida» y «memoria que sigue localizable», que es justo la situación en la que deja la static a un fd sin terminar.

bonusVarios descriptores a la vez

Entrega: get_next_line_bonus.c, get_next_line_bonus.h, get_next_line_utils_bonus.cRequisito: una sola variable static, varios fd alternados

El bonus pide dos cosas: usar una sola variable estática, y poder alternar llamadas sobre fd 3, 4 y 5 sin que se mezclen las líneas de uno con las de otro. Con un único buffer static compartido, leer del fd 4 machacaría el resto pendiente del fd 3.

	static char	*buf[MAX_FD];
	...
	p = gnl_strchr(buf[fd], CHAR_SEP);

La solución del usuario es indexar por fd: cada descriptor tiene su propio resto en buf[fd], y todos viven dentro de una variable static, el array. Lo curioso es que el usuario ya lo hizo así en la parte obligatoria, de modo que los ficheros _bonus son copias idénticas de los normales; la única diferencia es el #include "get_next_line_bonus.h". Leyendo dos ficheros alternados se obtiene:

[hola\n] [uno\n] [mundo\n] [dos\n] [\n] [NULL] ... [sin salto]

El precio del array es fijo: 1024 punteros (8 KB en 64 bits) en .bss, aunque solo se use uno. Los buffers en sí solo se reservan para los fd que se leen.

Qué te obliga a aprender — Que el estado de una función con memoria tiene que estar indexado por aquello que identifica a cada «cliente» — aquí, el número de fd. Es la misma idea que una tabla de sesiones en un servidor. Y que el número de descriptor no es más que un índice pequeño que el kernel asigna (empezando por el menor libre, normalmente el 3), lo que permite usarlo directamente como posición de un array.
