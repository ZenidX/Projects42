Cursus — A-Maze-ing rank 02

Un generador de laberintos en Python: lee una configuración, genera un laberinto (perfecto o tablero tipo Pac-Man) con un «42» en el centro, lo guarda en hexadecimal, lo dibuja en la terminal con un menú y empaqueta la generación como módulo pip reutilizable. Todo el repo pasa flake8 y mypy --strict, y cientos de laberintos generados pasan el maze_analyzer.py del enunciado, incluido el bonus de cero callejones.

De qué va el proyecto — Generar laberintos es un clásico de la informática porque, debajo del juego, es teoría de grafos pura: cada celda es un nodo, cada pared que se abre es una arista, y un laberinto perfecto (un único camino entre dos puntos cualesquiera) es exactamente un árbol generador de la cuadrícula. Por eso los algoritmos famosos de generación — el recursive backtracker (búsqueda en profundidad), Prim o Kruskal, que el propio enunciado cita — son los mismos que se usan para diseñar redes o en generación procedimental de contenido en videojuegos. Resolver el laberinto, a su vez, es buscar el camino más corto en un grafo.

El proyecto es además una pieza de algo más grande: el enunciado pide que el generador sea un paquete instalable con pip porque se reutilizará en un proyecto posterior, y el modo «no perfecto» tiene que producir un tablero directamente usable en un juego tipo Pac-Man (que en 42next es un proyecto del rank 04). Es el primer proyecto del cursus que piensa en quien va a usar tu código después.

La lectura va en dos pasos. Primero parse_lines convierte las líneas en un diccionario y rechaza lo que no tiene forma de configuración:

def parse_lines(lines: list[str]) -> Dict[str, str]:
    values: Dict[str, str] = {}
    for number, raw in enumerate(lines, start=1):
        line = raw.strip()
        if not line or line.startswith("#"):
            continue
        if "=" not in line:
            raise ConfigError(
                f"line {number}: expected KEY=VALUE, got '{line}'"
            )
        key, value = (part.strip() for part in line.split("=", 1))
        key = key.upper()
        if key not in MANDATORY_KEYS + OPTIONAL_KEYS:
            raise ConfigError(f"line {number}: unknown key '{key}'")
        if key in values:
            raise ConfigError(f"line {number}: key '{key}' is repeated")
        if not value:
            raise ConfigError(f"line {number}: '{key}' has no value")
        values[key] = value
    missing = [key for key in MANDATORY_KEYS if key not in values]
    if missing:
        raise ConfigError(f"missing mandatory key(s): {', '.join(missing)}")
    return values

Una clave desconocida o repetida es un error a propósito: así un WIDHT=20 con una errata no se ignora en silencio. Después build_config convierte cada valor y comprueba rangos y coherencia (la entrada dentro del laberinto, distinta de la salida…). Todo fallo se convierte en una ConfigError con un mensaje legible, incluido el de abrir el fichero:

def read_config(path: str) -> MazeConfig:
    try:
        with open(path, encoding="utf-8") as stream:
            lines = stream.readlines()
    except FileNotFoundError:
        raise ConfigError(f"configuration file not found: {path}")
    except IsADirectoryError:
        raise ConfigError(f"{path} is a directory, not a file")
    except (OSError, UnicodeDecodeError) as error:
        raise ConfigError(f"cannot read {path}: {error}")
    return build_config(parse_lines(lines))

El with es el context manager que pide el enunciado: el fichero se cierra aunque haya una excepción dentro.

Qué te obliga a aprender — A escribir un parser defensivo: validar antes de trabajar y convertir cada fallo en un mensaje útil en vez de un traceback. El truco es tener una excepción propia (ConfigError) que el main captura en un solo sitio, en lugar de llenar el código de print y sys.exit.

04La cuadrícula y las paredes

Fichero: mazegen/generator.py

El laberinto es una lista de listas, grid[y][x], y cada celda guarda sus paredes cerradas en 4 bits, los mismos del fichero de salida:

NORTH = 1
EAST = 2
SOUTH = 4
WEST = 8
ALL_WALLS = NORTH | EAST | SOUTH | WEST

Se empieza con todas las celdas a ALL_WALLS (15, F) y generar consiste solo en abrir paredes. Abrir una pared es tocar dos celdas: la propia y la vecina, con la dirección contraria. Por eso todo pasa por un único método:

def _open(self, cell: Cell, direction: int) -> None:
    """Open a wall on both sides, so the encoding stays coherent."""
    other = self._step(cell, direction)
    self.grid[cell[1]][cell[0]] &= ~direction
    self.grid[other[1]][other[0]] &= ~OPPOSITE[direction]

&= ~direction apaga ese bit y deja los otros tres como estaban. Como ninguna otra parte del código toca grid directamente, es imposible que dos vecinas no coincidan: la coherencia que comprueba maze_analyzer.py está garantizada por construcción. El borde exterior nunca se abre porque solo se abren paredes hacia celdas que existen.

Qué te obliga a aprender — Máscaras de bits, ahora en Python: cuatro booleanos empaquetados en un nibble que se consultan con & y se modifican con |= y &= ~. Y una trampa de coordenadas: la configuración usa (x, y) — columna, fila — pero una lista de listas se indexa grid[fila][columna]. Aquí todas las celdas son (x, y) y el cambio de orden ocurre solo al indexar.

05El «42»

Fichero: mazegen/generator.py

El dibujo es una plantilla de 7×5 donde # es una celda cerrada del todo:

PATTERN_42: Tuple[str, ...] = (
    "#.#.###",
    "#.#...#",
    "###.###",
    "..#.#..",
    "..#.###",
)
def _place_pattern(self) -> None:
    """Close the "42" cells, centred, keeping a free border around."""
    self.pattern_cells = set()
    self.pattern_omitted = False
    if not self.want_pattern:
        return
    if (self.width < PATTERN_WIDTH + 2
            or self.height < PATTERN_HEIGHT + 2):
        self.pattern_omitted = True
        return
    ox = (self.width - PATTERN_WIDTH) // 2
    oy = (self.height - PATTERN_HEIGHT) // 2
    cells = {
        (ox + col, oy + row)
        for row, line in enumerate(PATTERN_42)
        for col, char in enumerate(line)
        if char == "#"
    }
    for name, cell in (("entry", self.entry), ("exit", self.exit)):
        if cell in cells:
            raise MazeError(
                f"{name} {cell[0]},{cell[1]} falls inside the '42' "
                f"pattern"
            )
    self.pattern_cells = cells
  • Necesita 9×7 celdas como mínimo: la plantilla más un borde libre alrededor, para que el resto del laberinto pueda rodearla sin quedar partido. Si no cabe, se marca pattern_omitted y el programa imprime el mensaje de error que pide el enunciado.
  • La columna central de la plantilla (la que separa el 4 del 2) se deja libre a propósito: al centrar la plantilla, esa columna cae justo en el centro del tablero, que en modo Pac-Man tiene que ser pasillo (ahí empieza el jugador). Funciona también con anchos y altos pares, donde el analizador acepta cualquiera de las celdas de alrededor del centro.
  • Si la entrada o la salida caen dentro del «42», es un error claro.

Los algoritmos tratan las celdas del «42» como si no existieran (_free devuelve False), así que nunca se abre una pared hacia ellas y quedan cerradas por los cuatro lados.

06Laberinto perfecto: backtracker

Fichero: mazegen/generator.pyConfiguración: PERFECT=True
def _carve_backtracker(self) -> None:
    """Recursive backtracker (randomized depth-first search).

    Implemented with an explicit stack instead of recursion, so big
    mazes never hit Python's recursion limit.
    """
    start = self.entry
    visited: Set[Cell] = {start}
    stack: List[Cell] = [start]
    while stack:
        cell = stack[-1]
        options = [
            d for d in DIRECTIONS
            if self._free(self._step(cell, d))
            and self._step(cell, d) not in visited
        ]
        if not options:
            stack.pop()
            continue
        direction = self._rng.choice(options)
        nxt = self._step(cell, direction)
        self._open(cell, direction)
        visited.add(nxt)
        stack.append(nxt)

Se parte de la entrada. En cada paso se mira la celda de arriba de la pila: si tiene vecinas libres sin visitar, se elige una al azar, se abre la pared entre las dos y se avanza; si no le queda ninguna, se retrocede (pop). Termina cuando la pila se vacía, es decir, cuando ha vuelto al principio habiendo visitado todo.

Por qué sale perfecto: cada pared que se abre conecta una celda nueva con el laberinto ya hecho. Con N celdas libres se abren exactamente N−1 paredes y todas quedan conectadas: eso es un árbol, sin ningún bucle, con un único camino entre dos celdas cualesquiera. Una sala abierta de 3×3 es imposible, porque contendría un bucle.

La recursión clásica (visitar(celda) que se llama a sí misma) se ha cambiado por una pila explícita: en un laberinto de 200×200 el camino puede tener decenas de miles de pasos, y Python corta la recursión hacia los 1000 niveles.

El segundo algoritmo: Prim aleatorio (ALGORITHM=prim, bonus) 
def _carve_prim(self) -> None:
    """Randomized Prim: grow the maze from a random frontier wall."""
    start = self.entry
    visited: Set[Cell] = {start}
    frontier: List[Tuple[Cell, int]] = [(start, d) for d in DIRECTIONS]
    while frontier:
        index = self._rng.randrange(len(frontier))
        frontier[index], frontier[-1] = frontier[-1], frontier[index]
        cell, direction = frontier.pop()
        nxt = self._step(cell, direction)
        if not self._free(nxt) or nxt in visited:
            continue
        self._open(cell, direction)
        visited.add(nxt)
        frontier.extend((nxt, d) for d in DIRECTIONS)

En vez de avanzar por un único pasillo, Prim guarda la «frontera»: todas las paredes que separan lo ya construido de lo que falta. En cada paso saca una al azar (el intercambio con el último elemento hace que el pop sea O(1)) y, si al otro lado hay una celda libre sin visitar, la abre. También da un árbol, pero con otra textura: muchos pasillos cortos y ramificados en lugar de los largos y sinuosos del backtracker.

Por qué el backtracker — Es el algoritmo más sencillo que garantiza un laberinto perfecto, se explica en dos frases (DFS con retroceso) y da los pasillos largos y retorcidos que hacen bonito y difícil un laberinto. Toda la aleatoriedad sale de un único random.Random(seed): con la misma semilla y los mismos parámetros, las elecciones son idénticas y el laberinto también. Lo «aleatorio» de un ordenador es pseudoaleatorio.

07Tablero Pac-Man: trenzado

Fichero: mazegen/generator.pyConfiguración: PERFECT=False (por defecto)

Con PERFECT=False se genera primero un laberinto perfecto y luego se le quitan los callejones sin salida («trenzar», braiding):

def generate(self, seed: Optional[int] = None) -> List[List[int]]:
    if seed is not None:
        self.seed = seed
    self._rng = random.Random(self.seed)
    self.grid = [[ALL_WALLS] * self.width for _ in range(self.height)]
    self._place_pattern()
    if self.algorithm == "prim":
        self._carve_prim()
    else:
        self._carve_backtracker()
    if not self.perfect:
        self._braid()
        self._add_loops(2)
    return self.grid

Partir del laberinto perfecto da la conectividad total gratis: solo se añaden aberturas, nunca se quitan, así que todo lo que estaba conectado lo sigue estando.

def _braid(self) -> None:
    """Remove dead-ends by opening one extra wall in each of them.

    Opening towards another dead-end is preferred: it fixes two
    dead-ends with a single wall.
    """
    dead_ends = [c for c in self._free_cells() if self._degree(c) == 1]
    self._rng.shuffle(dead_ends)
    for cell in dead_ends:
        if self._degree(cell) != 1:
            continue
        options = self._closed_inner_walls(cell)
        self._rng.shuffle(options)
        options.sort(
            key=lambda d: self._degree(self._step(cell, d)) != 1
        )
        for direction in options:
            if self._try_open(cell, direction):
                break

Un callejón es una celda con una sola salida (grado 1). A cada uno se le abre una pared más, preferentemente hacia otro callejón (el sort pone primero las direcciones cuya vecina tiene grado 1), porque así una sola pared arregla dos. Cada pared abierta en un árbol crea exactamente un bucle nuevo.

Lo que no se puede hacer es abrir salas: los pasillos son de 2 celdas de ancho como mucho. _try_open abre la pared, mira si ha aparecido un bloque de 3×3 abierto del todo que la contenga y, si es así, la vuelve a cerrar:

def _try_open(self, cell: Cell, direction: int) -> bool:
    self._open(cell, direction)
    if self._creates_open_area(cell, direction):
        self._close(cell, direction)
        return False
    return True

def _block_open(self, x0: int, y0: int) -> bool:
    if not (self._inside((x0, y0)) and self._inside((x0 + 2, y0 + 2))):
        return False
    for y in range(y0, y0 + 3):
        for x in range(x0, x0 + 3):
            if x < x0 + 2 and not self.is_open((x, y), EAST):
                return False
            if y < y0 + 2 and not self.is_open((x, y), SOUTH):
                return False
    return True

Por último, _add_loops(2) garantiza las «dos rutas independientes» del enunciado en tableros pequeños donde el trenzado no basta. El número de bucles independientes de un grafo conexo es aristas − nodos + 1:

def _loops(self) -> int:
    cells = self._free_cells()
    edges = sum(self._degree(c) for c in cells) // 2
    return edges - len(cells) + 1

Las esquinas y el centro son pasillo siempre: el «42» deja un borde libre y su columna central abierta. Y si el tablero es tan pequeño que no caben dos bucles (un 2×2 tiene como mucho uno), el constructor lo rechaza con un MazeError en vez de entregar un tablero que no cumple.

Qué te obliga a aprender — A salir del árbol a propósito y razonar con grafos: grado de un nodo (un callejón es grado 1), ciclos (E − V + 1) y conectividad. Los únicos callejones que quedan son celdas encerradas por el propio «42», que el analizador tolera porque no se pueden abrir sin tocarlo. Resultado: con el config.txt por defecto, 0 callejones reales y 29 rutas independientes — el bonus de --max-dead-ends 0.

08Camino más corto y fichero de salida

Ficheros: mazegen/generator.py, maze_output.py

El camino más corto en un grafo sin pesos es una búsqueda en anchura (BFS): se exploran las celdas por orden de distancia a la entrada, y la primera vez que se llega a una es por el camino más corto. Basta guardar de dónde se vino para reconstruirlo al revés:

def solution(self) -> List[Cell]:
    self._require_grid()
    previous: Dict[Cell, Optional[Cell]] = {self.entry: None}
    queue: deque[Cell] = deque([self.entry])
    while queue:
        cell = queue.popleft()
        if cell == self.exit:
            break
        for nxt in self.neighbours(cell):
            if nxt not in previous:
                previous[nxt] = cell
                queue.append(nxt)
    if self.exit not in previous:
        return []
    path: List[Cell] = []
    step: Optional[Cell] = self.exit
    while step is not None:
        path.append(step)
        step = previous[step]
    path.reverse()
    return path

solution_directions lo convierte en letras comparando cada par de celdas consecutivas, y maze_output.py monta el fichero: una cifra hexadecimal por celda, fila a fila, una línea vacía, la entrada, la salida y el camino.

def format_maze(gen: MazeGenerator) -> str:
    lines = gen.to_hex()
    lines.append("")
    lines.append(f"{gen.entry[0]},{gen.entry[1]}")
    lines.append(f"{gen.exit[0]},{gen.exit[1]}")
    lines.append(gen.solution_directions())
    return "\n".join(lines) + "\n"

def _block_colour(gen: MazeGenerator, state: DisplayState, bx: int,
                  by: int, path_cells: Set[Cell],
                  path_links: Set[Tuple[Cell, Cell]]) -> int:
    x, y = bx // 2, by // 2
    if bx % 2 and by % 2:                       # a cell
        cell = (x, y)
        if cell in gen.pattern_cells:
            return state.pattern_colour
        if cell == gen.entry:
            return ENTRY_COLOUR
        if cell == gen.exit:
            return EXIT_COLOUR
        return PATH_COLOUR if cell in path_cells else OPEN
    if bx % 2:                                  # horizontal wall
        above, below = (x, y - 1), (x, y)
        if 0 < by < 2 * gen.height and gen.is_open(above, SOUTH):
            return PATH_COLOUR if (above, below) in path_links else OPEN
        return _wall_colour(gen, state, [above, below])
    if by % 2:                                  # vertical wall
        left, right = (x - 1, y), (x, y)
        if 0 < bx < 2 * gen.width and gen.is_open(left, EAST):
            return PATH_COLOUR if (left, right) in path_links else OPEN
        return _wall_colour(gen, state, [left, right])
    corners = [(x - 1, y - 1), (x, y - 1), (x - 1, y), (x, y)]
    return _wall_colour(gen, state, corners)

12Puntos delicados

  • Coherencia de paredes. Abrir una pared es tocar dos celdas: resuelto con un único _open por el que pasa todo.
  • El «42» y la conectividad. Borde libre alrededor y columna central abierta; los callejones que deja dentro del 4 y del 2 son los «enclosed» que tolera el analizador.
  • Perfecto de verdad. El backtracker abre N−1 paredes, ni una más. En modo Pac-Man, quitar una sola pared no basta: hacen falta al menos dos bucles.
  • Zonas de 3×3. Al trenzar es fácil abrir una sala sin querer: cada pared nueva se comprueba y se deshace si la crea.
  • Coordenadas. (x, y) en todo el código; grid[y][x] solo al indexar.
  • Recursión. Un DFS recursivo revienta en laberintos grandes; aquí es una pila.
  • Nunca un traceback. ConfigError, MazeError y OSError se capturan en main; Ctrl-C y Ctrl-D también.
  • Modificación en directo. El enunciado avisa de que puede pedirse un cambio pequeño en la evaluación: cambiar el dibujo del «42» es tocar PATTERN_42; un color nuevo, una línea en WALL_COLOURS; una clave de configuración, OPTIONAL_KEYS y build_config.
