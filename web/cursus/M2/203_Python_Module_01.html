Cursus — Python Module 01 en curso

«Code Cultivation»: del programa suelto a las clases. El mismo huerto del módulo anterior, ahora modelado con objetos. Módulo en curso: aquí están explicados los ejercicios ya hechos (ex0, ex1 y ex2); el resto se añadirá más adelante.

Estado: ex0 y ex1 terminados · ex2 a medias (versión en disco, sin commit) · ex3–ex6 pendientes.

  • ex0 — ft_garden_intro
  • ex1 — ft_garden_data
  • ex2 — ft_plant_growth
  • ex3–ex6 — pendientes
De funciones sueltas a objetos — En el Module 00 cada fichero era una sola función y estaba prohibido el bloque if __name__ == "__main__":. Este módulo cambia las reglas: ahora cada fichero es un programa que se ejecuta con python3 fichero.py, el bloque __main__ está permitido y, desde ex1, todo debe ir en clases. Las anotaciones de tipo pasan a ser obligatorias en todas las funciones y métodos (se comprueban con mypy), y sigue mandando flake8. La progresión del enunciado va paso a paso: variables sueltas → una clase → métodos que cambian el estado → constructor → encapsulación → herencia → métodos estáticos y de clase. Viniendo de C, la clase es lo que harías con un struct y un puñado de funciones que reciben un puntero a él, solo que aquí datos y funciones viajan juntos y el puntero se llama self.

ex0ft_garden_intro

Entrega: ft_garden_intro.pyAutorizado: print()
if __name__ == "__main__":
    name = "Rose"
    height = "25 cm"
    age = "30 days"
    print("=== Welcome to My Garden ===")
    print(f"Plant: {name}")
    print(f"Height: {height}")
    print(f"Age: {age}")
    print("")
    print("=== End of Program ===")
$> python3 ft_garden_intro.py
=== Welcome to My Garden ===
Plant: Rose
Height: 25 cm
Age: 30 days

=== End of Program ===

Tres variables simples y unos print, todo dentro del bloque __main__. La altura sale como 25 cm (con espacio) en lugar del 25cm del ejemplo; el enunciado avisa de que la salida no se comprueba de forma estricta.

Qué te obliga a aprender — Dónde empieza un programa en Python. En C la respuesta era fija: main. En Python no hay función principal: el intérprete ejecuta el fichero de arriba abajo. __name__ es una variable que Python rellena solo: vale "__main__" si el fichero se ejecuta directamente, y el nombre del módulo si otro fichero lo importa. El if sirve para que el código de prueba no se ejecute al importar — justo lo que hacía el main.py del módulo anterior con tus funciones. El enunciado anuncia además que en la evaluación habrá que añadir en directo la línea shebang (#!/usr/bin/env python3), que permite ejecutar el script como ./ft_garden_intro.py tras darle permiso de ejecución.

ex1ft_garden_data

Entrega: ft_garden_data.pyAutorizado: print()
class Plant:
    def __init__(self, name: str, height: str, age: str) -> None:
        self.name = name
        self.height = height
        self.age = age

    def show(self) -> None:
        print(f"{self.name}: {self.height}, {self.age}")


if __name__ == "__main__":
    plant1 = Plant("Rose", "25cm", "30 days old")
    plant2 = Plant("Sunflower", "80cm", "45 days old")
    plant3 = Plant("Cactus", "15cm", "120 days old")

    print("=== Garden Plant Registry ===")
    plant1.show()
    plant2.show()
    plant3.show()
$> python3 ft_garden_data.py
=== Garden Plant Registry ===
Rose: 25cm, 30 days old
Sunflower: 80cm, 45 days old
Cactus: 15cm, 120 days old

Una clase Plant con constructor __init__ y un método show. Cada Plant(...) crea un objeto nuevo y llama a __init__ con él como self, que guarda los tres atributos. plant1.show() es azúcar para Plant.show(plant1).

Una rareza de diseño: la altura y la edad se guardan como cadenas ya formateadas ("25cm", "30 days old"), con las unidades dentro. Para mostrar basta, pero en cuanto haya que hacer cuentas con ellas — que es justo lo que pide ex2 — habrá que sacar el número del texto. El propio enunciado lo deja caer: «¿qué problemas pueden aparecer con más plantas? Puede que tengas que hacer evolucionar tu enfoque».

Qué te obliga a aprender — La idea de clase como molde: un único modelo para todas las plantas en lugar de tres juegos de variables sueltas. Es el struct de C con las funciones dentro: self hace el papel del puntero al struct que en C pasabas a mano (t_list *lst), y __init__ el de la función que reservaba e inicializaba el nodo — pero sin malloc: Python crea el objeto y lo libera cuando nadie lo usa. El enunciado sugería instanciar primero y asignar los atributos después; aquí ya se hace todo en el constructor, lo que en realidad corresponde a ex3 («Plant Factory»), y el enunciado lo admite.

ex2ft_plant_growth a medias

Entrega: ft_plant_growth.pyAutorizado: print(), range(), round()

El enunciado pide reutilizar la clase de ex1, añadirle métodos grow() y age(), simular una semana de crecimiento día a día y mostrar al final cuánto ha crecido. El fichero está todavía a medio camino; esto es lo que hay ahora mismo en disco:

class Plant:
    def __init__(self, name, height, age):
        self.name = name
        self.height = height
        self.age = age

    def show(self):
        print(f"{self.name}: {self.height}, {self.age}")

    def grow(self, growth_amount):
        self.height = f"{int(self.height[:-2]) + growth_amount}cm"
        self.age = f"{int(self.age.split()[0]) + 1} days old"

    def age(self, days):
        self.age = f"{int(self.age.split()[0]) + days} days old"

Como la altura y la edad son cadenas (decisión de ex1), cada método tiene que desmontar el texto, operar y volver a montarlo: self.height[:-2] corta las dos últimas letras ("cm") y self.age.split()[0] parte la cadena por espacios y se queda con el primer trozo ("30"). grow suma la altura y además un día de edad.

El programa principal se ha movido a una función main(), llamada desde el bloque __main__; de momento crea tres plantas y las muestra, igual que ex1:

$> python3 ft_plant_growth.py
=== Garden Plant Registry ===
Rose: 25cm, 30 days old
Sunflower: 80cm, 45 days old
Cactus: 15cm, 120 days

(La tercera planta se creó con "120 days", sin «old», y así sale.)

Cosas a tener en cuenta para terminarlo:

  • Ojo: el método age queda tapado por el atributo age. En __init__, self.age = age crea un atributo del objeto con ese nombre, y en Python los atributos del objeto se buscan antes que los métodos de la clase. Así que plant.age(1) intenta llamar a una cadena: 
    >>> p = Plant("Rose", "25cm", "30 days old")
>>> p.grow(1); p.show()
Rose: 26cm, 31 days old
>>> p.age(1)
TypeError: 'str' object is not callable
    Como el enunciado exige que el método se llame age(), es el atributo el que tendrá que llevar otro nombre.
  • Alturas con decimales. El ejemplo del enunciado crece 0,8 cm al día (25.0cm → 25.8cm), pero int(self.height[:-2]) solo entiende enteros: con "25.8cm" lanzaría ValueError.
  • Falta la simulación de la semana (el bucle de 7 días con range) y el resumen «Growth this week».
  • flake8 y mypy. A diferencia de ex1, aquí no hay anotaciones de tipo, que en este módulo son obligatorias en todas las funciones y métodos. Y flake8 marca tres avisos (E302 y E305: faltan dos líneas en blanco antes y después de main; W291: espacio al final de def main(): ).
Qué te obliga a aprender — Que un objeto tiene estado y que los métodos lo cambian: tras grow() la planta ya no es la misma. Y, de rebote, una lección que en C venía impuesta por los tipos: guardar los datos en la forma con la que se calcula (números) y convertirlos a texto solo al mostrarlos. En C int height no podía contener "cm"; Python te deja meter lo que quieras en un atributo, y el precio es tener que parsearlo cada vez. También aparece el espacio de nombres compartido de un objeto: atributos y métodos viven en el mismo diccionario de nombres, algo que en C, con un struct y funciones aparte, no podía chocar.
