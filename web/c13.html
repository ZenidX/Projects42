Árboles binarios: la estructura donde la recursión deja de ser un truco y pasa a ser la forma natural de pensar. Ocho ejercicios sobre creación, los tres recorridos clásicos, el árbol binario de búsqueda y un recorrido por niveles que ya pide una cola.

  • ex00 — create_node

  • ex02 — apply_infix

  • ex05 — search_item

La estructura del módulo — El nodo, entregado en ft_btree.h, tiene dos hijos en vez del único next de las listas: 
typedef struct s_btree
{
	struct s_btree	*left;
	struct s_btree	*right;
	void			*item;
}	t_btree;
Ese doble enlace lo cambia todo: la estructura ya no es una línea, es una ramificación. Y por eso casi todas las funciones se escriben solas de forma recursiva: «haz algo con la raíz, luego repite lo mismo con el subárbol izquierdo y con el derecho». Cada rama es, a su vez, un árbol completo — esa autosemejanza es lo que hace que la recursión encaje como un guante.

ex00btree_create_node

Entregable: btree_create_node.c, ft_btree.hAutorizadas: malloc

Crear un nodo con su item y el resto a 0.

node = malloc(sizeof(t_btree));
if (!node)
	return (NULL);
node->left = NULL;
node->right = NULL;
node->item = item;
return (node);
Qué te obliga a aprender — El caso base de todo lo que viene. Un nodo recién creado es una hoja: sin hijos (left y right a NULL). Ese NULL es lo que luego detiene la recursión en cada recorrido; si dejaras los punteros sin inicializar, cada recorrido se lanzaría contra memoria basura.

ex01btree_apply_prefix

Entregable: btree_apply_prefix.c, ft_btree.hAutorizadas: ninguna

Recorrido preorden: raíz, luego izquierda, luego derecha.

if (!root)
	return ;
applyf(root->item);
btree_apply_prefix(root->left, applyf);
btree_apply_prefix(root->right, applyf);
Qué te obliga a aprender — La plantilla de la recursión sobre árboles: comprobar NULL (caso base) y bajar por los dos lados. En preorden se visita antes de bajar. Sirve para copiar o serializar un árbol: como la raíz sale primero, quien lee la secuencia puede reconstruir la estructura de arriba abajo.

ex02btree_apply_infix

Entregable: btree_apply_infix.c, ft_btree.hAutorizadas: ninguna

Recorrido inorden: izquierda, raíz, derecha.

if (!root)
	return ;
btree_apply_infix(root->left, applyf);
applyf(root->item);
btree_apply_infix(root->right, applyf);
Qué te obliga a aprender — El mismo esqueleto, movida una sola línea: la visita va entre las dos bajadas. Y ahí está la magia — sobre un árbol binario de búsqueda, el inorden saca los elementos ordenados de menor a mayor. Cambiar el momento de la visita cambia por completo el resultado, con el mismo recorrido.

ex03btree_apply_suffix

Entregable: btree_apply_suffix.c, ft_btree.hAutorizadas: ninguna

Recorrido postorden: izquierda, derecha, raíz.

if (!root)
	return ;
btree_apply_suffix(root->left, applyf);
btree_apply_suffix(root->right, applyf);
applyf(root->item);
Qué te obliga a aprender — La tercera posición de la visita: después de bajar por ambos lados. Es el orden que necesitas para liberar un árbol (borras los hijos antes que el padre, o dejarías nodos huérfanos) y para evaluar expresiones: un nodo se calcula cuando sus dos operandos ya están resueltos. Preorden, inorden y postorden son la misma recursión con la visita en un sitio distinto.

ex04btree_insert_data

Entregable: btree_insert_data.c, ft_btree.hAutorizadas: btree_create_node

Insertar respetando el orden: los menores a la izquierda, los iguales o mayores a la derecha, usando un comparador tipo strcmp.

if (!*root)
{
	*root = btree_create_node(item);
	return ;
}
if (cmpf(item, (*root)->item) < 0)
	btree_insert_data(&(*root)->left, item, cmpf);
else
	btree_insert_data(&(*root)->right, item, cmpf);
Qué te obliga a aprender — Aquí se construye el árbol binario de búsqueda (BST): la propiedad de «menores a la izquierda, mayores a la derecha» es la que convierte un árbol en un buscador. Se combina la recursión con el t_btree ** de C 12: al llegar a un hueco (*root == NULL) hay que escribir ahí el nodo nuevo, y para eso necesitas la dirección del puntero, no su valor.

ex05btree_search_item

Entregable: btree_search_item.c, ft_btree.hAutorizadas: ninguna

Buscar el primer item que casa con data_ref, recorriendo en inorden. Devuelve NULL si no está.

if (!root)
	return (NULL);
found = btree_search_item(root->left, data_ref, cmpf);
if (found)
	return (found);
if (cmpf(root->item, data_ref) == 0)
	return (root->item);
return (btree_search_item(root->right, data_ref, cmpf));
Qué te obliga a aprender — Recursión que devuelve valor y corta en cuanto encuentra: si el subárbol izquierdo ya trae un resultado, no se mira el resto. El enunciado pide orden inorden, así que se busca izquierda → raíz → derecha. Ojo al matiz: aquí se recorre sin aprovechar la propiedad del BST; si se aprovechara (ir solo a un lado según el comparador), la búsqueda sería O(log n) en un árbol equilibrado — la razón de ser de los árboles de búsqueda.

ex06btree_level_count

Entregable: btree_level_count.c, ft_btree.hAutorizadas: ninguna

Devolver la longitud de la rama más larga (la altura del árbol).

if (!root)
	return (0);
left = btree_level_count(root->left);
right = btree_level_count(root->right);
if (left > right)
	return (left + 1);
return (right + 1);
Qué te obliga a aprender — La recursión que calcula en vez de solo recorrer: la altura de un nodo es 1 más la altura de su hijo más alto. El vacío mide 0, una hoja mide 1. Es el patrón «resuelve los dos subproblemas y combínalos» (divide y vencerás), y esa altura es la que determina si un BST está equilibrado o degenerado en una lista.

ex07btree_apply_by_level

Entregable: btree_apply_by_level.c, ft_btree.hAutorizadas: malloc, free

Recorrer el árbol nivel por nivel (anchura). A cada nodo se le pasa su nivel y si es el primero de su nivel.

head = new_qnode(root, 0);
while (head)
{
	applyf(head->node->item, head->level, head->level != prev);
	prev = head->level;
	tail = enqueue_kids(tail, head->node, head->level);  /* encola hijos */
	tmp = head;
	head = head->next;
	free(tmp);
}
Qué te obliga a aprender — El recorrido en anchura (BFS) no sale gratis con recursión: necesita una cola (FIFO). Se saca un nodo, se procesa y se encolan sus hijos al final; la cola garantiza que un nivel entero se visita antes que el siguiente. Por eso el ejercicio autoriza malloc y free: hay que construir esa cola con nodos auxiliares y liberarlos al vaciarla. Es la estructura opuesta a la pila que usa la recursión (que hace, implícitamente, un recorrido en profundidad). El flag «primero del nivel» se deduce de comparar el nivel actual con el del nodo anterior.
