Truquitos

#1Clonar tu repo de Vogsphere

Necesitas: clave SSH subida a la intra Dónde: red del campus (o VPN de 42)

Cada proyecto de la intra te da una URL de entrega del tipo git@vogsphere.42barcelona.com:vogsphere/intra-uuid-...-tulogin. Es git por SSH: para que funcione, tu clave pública tiene que estar registrada en tu cuenta de la intra.

1. Comprueba (o genera) tu clave SSH

ls -la ~/.ssh

Si no tienes ninguna pareja (id_ed25519 + id_ed25519.pub), genera una:

ssh-keygen -t ed25519 -C "tulogin@42barcelona"

Y sube la pública (~/.ssh/id_ed25519.pub) en la intra: Settings → SSH Keys. En los iMacs del campus suele estar ya gestionado, pero conviene verificarlo — sobre todo si trabajas desde tu portátil.

2. Prueba la conexión

ssh -T git@vogsphere.42barcelona.com

Si autentica, vas bien. Si responde Permission denied (publickey), el problema está en la clave (no está subida, o ssh no está ofreciendo la correcta).

3. Clona (y renombra de paso)

El nombre del repo es un UUID kilométrico; pásale un segundo argumento a git clone para que la carpeta se llame como el proyecto:

git clone git@vogsphere.42barcelona.com:vogsphere/intra-uuid-...-tulogin shell00
cd shell00
Si da timeout o no resuelve el host — Vogsphere solo es accesible desde la red del campus. Fuera de 42 Barcelona necesitas la VPN de la escuela activa; sin ella, ni ssh -T ni el clone van a llegar.

Para entregar: copia dentro del clon solo las carpetas exNN/ con los archivos pedidos, y haz git add, commit y push. La Moulinette corrige lo que hay en el repo en el momento del deadline — un archivo de más o un nombre mal escrito es un cero.

#2norminette: instalar y usar

Qué es: el linter oficial de la Norma de 42 Lenguaje: Python (pip)

La norminette ("pequeña norma", en francés) es la herramienta oficial de 42 que comprueba si tu C cumple la Norma: header 42, tabs, máximo 25 líneas por función, sin for, etc. Es exactamente lo mismo que ejecuta la Moulinette, así que si pasa en local, pasa en la corrección.

Instalación

En los puestos del campus ya viene instalada. En tu máquina:

pip install norminette

Uso básico

norminette archivo.c          # un archivo
norminette .                  # todo el directorio actual, recursivo
norminette ex01/ ex02/        # varios directorios a la vez

Salida típica con errores:

ex01/ft_ft.c
Error: TOO_MANY_LINES          (line:  45, col:  1):  Too many lines in function
Error: SPACE_REPLACE_TAB       (line:  12, col:  3):  Found space when expecting tab
Error: MISSING_FUNCTION_HEADER (line:   1, col:  1):  Missing function header

Y cuando todo está bien:

ex01/ft_ft.c: OK!

Flags útiles

norminette -R CheckForbiddenSourceHeader .   # ignorar una regla concreta
norminette --version                         # qué versión de la Norma aplica
Truco — Las soluciones de C de este repo se verificaron con norminette -R CheckForbiddenSourceHeader (la regla del header se salta porque el header 42 se genera aparte). En CI puedes usar la GitHub Action oficial 42School/norminette o alexandregv/norminette-action: por debajo ejecutan exactamente este mismo comando.

#3norminette en modo continuo

Objetivo: ver los errores de Norma al guardar, no al entregar Opciones: entr · watch · vim

Pasar la norminette a mano después de cada cambio es un rollo. Tres formas de que se ejecute sola:

Opción A — entr (la recomendada)

Vigila archivos y relanza un comando cada vez que cambian. Ligera y agnóstica del editor: déjala corriendo en una pestaña de tmux mientras editas en otra.

sudo apt install entr

find . -name "*.c" -o -name "*.h" | entr -c norminette .

Cada vez que guardas, re-ejecuta norminette automáticamente. El flag -c limpia la terminal entre ejecuciones.

Opción B — watch (cero dependencias)

watch -n 2 norminette .

Re-ejecuta cada 2 segundos, cambie algo o no. Menos elegante que entr, pero funciona en cualquier sitio sin instalar nada.

Opción C — dentro de vim

El plugin norminette-vim usa syntastic para marcar los errores de Norma inline, en el propio código, al abrir o guardar un .c:

git clone https://github.com/alexandregv/norminette-vim \
  ~/.vim/pack/syntax/start/norminette-vim

Y en tu ~/.vimrc:

let g:syntastic_c_checkers = ['norminette', 'gcc']
let g:syntastic_check_on_open = 1
Cuál elegir — Si vives en la terminal, entr: no depende del editor y solo trabaja cuando hay cambios. Si editas en vim todo el día, el plugin es lo más cómodo — ves el error en la línea exacta sin salir del archivo.
