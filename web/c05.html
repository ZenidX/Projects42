C Piscine — C 05

El módulo de la recursión y la aritmética: factorial, potencia, Fibonacci, raíz cuadrada, primos y un cierre con las diez reinas. Casi todo se puede hacer de dos maneras — con un bucle o llamándose a sí misma— y el módulo te obliga a comparar ambas.

El concepto que vertebra el módulo: recursión vs. iteración — Una función iterativa resuelve el problema con un bucle y unas pocas variables: la memoria que usa es constante. Una función recursiva se llama a sí misma con un caso más pequeño hasta tocar un caso base; cada llamada pendiente ocupa un marco (stack frame) en la pila, con sus parámetros y su punto de retorno. C05 empareja deliberadamente factorial y potencia en versión iterativa y recursiva para que veas que resuelven lo mismo con costes distintos: la recursión es más corta y se lee como la definición matemática, pero cada nivel cuesta pila, y si te olvidas del caso base o no reduces el problema, la pila se desborda (stack overflow) y el programa muere. Entender esto aquí, con funciones de tres líneas, es lo que te permite después leer un árbol o un backtracking sin perderte. (El prólogo del enunciado cita al Sombrero Seleccionador de Harry Potter para acto seguido avisar de que el proyecto no va de magia; es el humor absurdo de costumbre.)

ex00ft_iterative_factorial

Entrega: ft_iterative_factorial.cAutorizado: nada

Factorial iterativo: n! = 1·2·3·…·n. Si el argumento no es válido (negativo) devuelve 0; los desbordamientos no hay que tratarlos.

int	ft_iterative_factorial(int nb)
{
	int	result;
	int	i;

	if (nb < 0)
		return (0);
	result = 1;
	i = 1;
	while (i <= nb)
	{
		result *= i;
		i++;
	}
	return (result);
}

El acumulador arranca en 1 (el elemento neutro del producto), no en 0 — si empezara en cero todo el resultado sería cero. Con nb == 0 el bucle no se ejecuta y devuelve 1, que es la definición correcta de 0! = 1.

Qué te obliga a aprender — El patrón acumulador: una variable que guarda el resultado parcial mientras un índice recorre el rango. Es la forma iterativa canónica y la base de casi todos los bucles de cómputo que escribirás. Memoria constante, sin pila que crezca.

ex01ft_recursive_factorial

Entrega: ft_recursive_factorial.cAutorizado: nada

El mismo factorial, ahora recursivo.

int	ft_recursive_factorial(int nb)
{
	if (nb < 0)
		return (0);
	if (nb <= 1)
		return (1);
	return (nb * ft_recursive_factorial(nb - 1));
}

Dos guardas antes de recurrir: el caso de error (nb < 0 → 0) y el caso base (nb <= 1 → 1, que cubre tanto 0! como 1!). Solo cuando ninguno se cumple la función se llama a sí misma con nb - 1.

Qué te obliga a aprender — La estructura de toda función recursiva: primero el caso base que detiene la recursión, después el paso que reduce el problema hacia ese caso. La expresión nb * ft_recursive_factorial(nb - 1) es literalmente la definición matemática n! = n · (n-1)!. Compárala con el bucle de ex00: mismo resultado, pero aquí hay nb marcos apilados a la vez. Con un factorial da igual; con recursiones profundas empieza a importar.

ex02ft_iterative_power

Entrega: ft_iterative_power.cAutorizado: nada

Potencia iterativa nb^power. Si power < 0 devuelve 0; por definición 0^0 = 1.

int	ft_iterative_power(int nb, int power)
{
	int	result;

	if (power < 0)
		return (0);
	result = 1;
	while (power > 0)
	{
		result *= nb;
		power--;
	}
	return (result);
}

Multiplicar nb por sí mismo power veces. El caso 0^0 sale gratis: con power == 0 el bucle no entra y queda result = 1, que es la convención que pide el enunciado.

Qué te obliga a aprender — Que el elemento neutro importa. Igual que el factorial empieza en 1, la potencia también, porque 1 es el neutro del producto. Y que los casos límite (power cero o negativo) no son excepciones que gestionar aparte: se caen solos del diseño si eliges bien el valor inicial y la condición del bucle.

ex03ft_recursive_power

Entrega: ft_recursive_power.cAutorizado: nada

La misma potencia, recursiva.

int	ft_recursive_power(int nb, int power)
{
	if (power < 0)
		return (0);
	if (power == 0)
		return (1);
	return (nb * ft_recursive_power(nb, power - 1));
}

Caso base power == 0 → 1; paso nb^p = nb · nb^(p-1). Fíjate en que aquí el parámetro que se reduce es power, no nb: nb viaja intacto por toda la cadena de llamadas.

Qué te obliga a aprender — Que en una recursión no todos los argumentos cambian. Uno es el que decrece hacia el caso base (power) y otro es un dato fijo que se arrastra (nb). Distinguir cuál es cuál es exactamente lo que tendrás que hacer con recursiones de verdad, como el backtracking de ex08.

ex04ft_fibonacci

Entrega: ft_fibonacci.cAutorizado: nada

Devuelve el elemento index de Fibonacci (0, 1, 1, 2, 3, 5…), con el primero en el índice 0. Debe ser recursiva. Si index < 0 devuelve -1.

int	ft_fibonacci(int index)
{
	if (index < 0)
		return (-1);
	if (index == 0)
		return (0);
	if (index == 1)
		return (1);
	return (ft_fibonacci(index - 1) + ft_fibonacci(index - 2));
}

Aquí hay dos casos base (0 y 1) porque cada término depende de los dos anteriores, y dos llamadas recursivas por nivel.

Qué te obliga a aprender — La recursión en árbol, y su lado oscuro. fib(n) vuelve a calcular fib(n-2) por dos caminos distintos, y fib(n-3) tres veces, y así: el número de llamadas crece exponencialmente. fib(40) ya dispara más de mil millones de llamadas. El enunciado exige la versión recursiva justamente para que sientas esa explosión, y para que más adelante entiendas por qué existen la memoización y la programación dinámica. La versión iterativa (dos variables que se van pisando) lo haría en O(n) y sin pila; que la piscine te prohíba usarla aquí es pedagógico, no práctico.

ex05ft_sqrt

Entrega: ft_sqrt.cAutorizado: nada

Raíz cuadrada entera: devuelve la raíz si es exacta, o 0 si no lo es (o si nb no tiene raíz entera).

int	ft_sqrt(int nb)
{
	long	i;

	if (nb < 1)
		return (0);
	i = 1;
	while (i * i < nb)
		i++;
	if (i * i == nb)
		return (i);
	return (0);
}

Se prueban candidatos 1, 2, 3… hasta que i·i alcanza o supera nb. Si lo iguala exactamente, esa es la raíz; si lo supera sin igualarlo, nb no es un cuadrado perfecto y la respuesta es 0.

Qué te obliga a aprender — Dos cosas. (1) El desbordamiento como problema de tipos: i·i puede superar los ~2.147 millones que aguanta un int antes de que i llegue a la raíz de un nb grande. Declarar i como long evita que el producto se desborde y el bucle nunca pare. Es tu primer encuentro con "el tipo importa aunque el resultado quepa". (2) Que a veces el algoritmo obvio (probar en orden) es suficiente; optimizarlo con búsqueda binaria es una mejora que puedes razonar después.

ex06ft_is_prime

Entrega: ft_is_prime.cAutorizado: nada

Devuelve 1 si nb es primo, 0 si no. Ni 0 ni 1 son primos (ni los negativos).

int	ft_is_prime(int nb)
{
	long	i;

	if (nb < 2)
		return (0);
	i = 2;
	while (i * i <= nb)
	{
		if (nb % i == 0)
			return (0);
		i++;
	}
	return (1);
}

La clave está en la condición i·i <= nb: no hace falta probar divisores más allá de la raíz cuadrada de nb, porque si nb tuviera un divisor mayor que su raíz, su pareja sería uno menor que ya habríamos encontrado.

Qué te obliga a aprender — Optimización por razonamiento matemático, no por trucos de código. Comprobar divisores hasta nb funciona pero es lento; parar en √nb convierte un O(n) en O(√n) y solo requiere entender por qué los divisores vienen en parejas. Otra vez long para que i·i no se desborde con primos grandes. La aritmética de % (resto) es el detector de divisibilidad de todo el módulo.

ex07ft_find_next_prime

Entrega: ft_find_next_prime.cAutorizado: nada

Devuelve el primo inmediatamente superior o igual a nb.

static int	ft_is_prime(int nb)
{
	/* … idéntica a ex06 … */
}

int	ft_find_next_prime(int nb)
{
	while (!ft_is_prime(nb))
		nb++;
	return (nb);
}

Se prueba nb, y si no es primo se sube de uno en uno hasta encontrar el primero que lo sea. Como el propio nb cuenta, si ya es primo se devuelve tal cual.

Qué te obliga a aprender — La reutilización como diseño: en vez de reescribir la primalidad, la encapsulas en un helper y la llamas. Como el helper no debe verse desde fuera del archivo, se declara static — tu primera decisión consciente de ámbito (qué es público y qué es privado dentro de un .c). La Norma limita a 5 funciones por archivo y este es un buen ejemplo de por qué partir un problema en piezas pequeñas ayuda a que cada una quepa y se lea.

ex08ft_ten_queens_puzzle

Entrega: ft_ten_queens_puzzle.cAutorizado: write

Mostrar todas las formas de colocar diez reinas en un tablero 10×10 sin que ninguna ataque a otra, y devolver el número total de soluciones (son 724). Cada solución se imprime como diez cifras: la n-ésima cifra es la fila de la reina en la columna n.

static int	is_valid(int *board, int col, int row)
{
	int	i;

	i = 0;
	while (i < col)
	{
		if (board[i] == row)
			return (0);
		if (col - i == row - board[i] || col - i == board[i] - row)
			return (0);
		i++;
	}
	return (1);
}

static int	solve(int *board, int col)
{
	int	row;
	int	count;

	if (col == 10)
	{
		print_board(board);
		return (1);
	}
	row = 0;
	count = 0;
	while (row < 10)
	{
		if (is_valid(board, col, row))
		{
			board[col] = row;
			count += solve(board, col + 1);
		}
		row++;
	}
	return (count);
}

El truco de la representación: como cada columna lleva exactamente una reina, board[col] = row basta para describir el tablero, y así dos reinas nunca comparten columna por construcción. is_valid solo tiene que comprobar, contra las reinas ya colocadas, la misma fila (board[i] == row) y las dos diagonales (cuando la distancia en columnas iguala la distancia en filas).

Qué te obliga a aprender — El backtracking, que es la síntesis de todo C05. solve avanza columna a columna probando filas; cuando una fila es válida la fija y baja un nivel (recursión), y cuando agota las diez filas de una columna simplemente vuelve — "deshace" — y prueba la siguiente opción del nivel anterior. La pila de llamadas es el tablero parcial: no necesitas guardar y restaurar estado a mano porque cada marco recuerda su propio col y su propio row. Colocar el caso base (col == 10: solución completa, imprime y suma 1) y acumular los retornos de las ramas es el mismo esqueleto del factorial recursivo, pero ramificado. Si entiendes por qué esto explora exactamente todas las combinaciones válidas y ninguna inválida, tienes la llave de laberintos, sudokus y parsers.
