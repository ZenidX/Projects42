C Piscine — C 04

El puente entre texto y números. Se escriben ft_strlen, ft_putstr, ft_putnbr, ft_atoi y sus versiones en base arbitraria. 6 ejercicios (ex00–ex05).

Números, bases y representación — El tema del módulo. Un int en memoria es un patrón de bits; «42» es solo una forma de escribirlo en base 10. La misma cantidad es 101010 en binario, 2a en hexadecimal o 52 en octal: cambia la notación, no el valor. Convertir texto→número (atoi) y número→texto (putnbr) es traducir entre esas representaciones, y hacerlo en cualquier base obliga a entender la notación posicional de raíz: cada dígito vale su símbolo por la base elevada a su posición. Este módulo también es el primer contacto con los límites del int —el overflow— y con el caso más venenoso de todo C: INT_MIN, el negativo que no tiene positivo.

ex00ft_strlen

Prototipo: int ft_strlen(char *str)

Contar y devolver el número de caracteres de una cadena.

int	ft_strlen(char *str)
{
	int	i;

	i = 0;
	while (str[i])
		i++;
	return (i);
}

Se cuenta avanzando hasta el \0. El índice donde está el terminador coincide con la longitud, porque contamos desde 0. Es la operación más básica sobre cadenas y aparece, explícita o disimulada, en casi todos los demás ejercicios de la piscina.

Concepto — medir cuesta O(n). En C, saber la longitud de una cadena no es gratis: hay que recorrerla entera cada vez. Por eso escribir while (i < strlen(s)) dentro de un bucle es un clásico error de rendimiento (recorre la cadena en cada vuelta). Lenguajes como Python o Rust guardan la longitud aparte justamente para no pagar este peaje.

ex01ft_putstr

Prototipo: void ft_putstr(char *str)Autorizada: write

Imprimir una cadena por la salida estándar.

void	ft_putstr(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		write(1, &str[i], 1);
		i++;
	}
}

Se escribe carácter a carácter con write sobre el descriptor 1 (la salida estándar). Se pasa &str[i] porque write quiere una dirección y un número de bytes; aquí, un byte cada vez.

Concepto — write es la salida de verdad. Sin printf (que no está autorizado), toca hablar directamente con el kernel vía la syscall write. El 1 es stdout; el 2, stderr. Todo lo que imprime tu programa acaba, tarde o temprano, en una llamada como esta: printf no es más que una capa cómoda por encima.

ex02ft_putnbr

Prototipo: void ft_putnbr(int nb)Autorizada: write

Mostrar un entero, cubriendo todo el rango de int (incluido el mínimo).

void	ft_putnbr(int nb)
{
	long	n;
	char	c;

	n = nb;
	if (n < 0)
	{
		write(1, "-", 1);
		n = -n;
	}
	if (n >= 10)
		ft_putnbr(n / 10);
	c = n % 10 + '0';
	write(1, &c, 1);
}

Se copia nb a un long antes de nada. La recursión imprime los dígitos en orden: para 423, la llamada con 42 ocurre antes de imprimir el 3, así que las centenas y decenas salen primero. La conversión dígito→carácter es el + '0' que veíamos en C02, ahora en su uso real.

Concepto — INT_MIN, el número maldito. El rango de un int es asimétrico: de −2147483648 a +2147483647. El mínimo no tiene positivo representable, así que -n con n = INT_MIN se desborda (comportamiento indefinido). El truco de copiar a long —que sí tiene sitio para 2147483648— esquiva la trampa. Reconocer este caso límite es un rito de paso: casi todo el mundo lo suspende la primera vez.

ex03ft_atoi

Prototipo: int ft_atoi(char *str)

Convertir el principio de una cadena en un int: espacios iniciales opcionales, una tanda de signos +/-, y luego dígitos hasta el primer carácter no numérico. Con varios -, el resultado es negativo si su número es impar.

int	ft_atoi(char *str)
{
	int	i;
	int	sign;
	int	result;

	i = 0;
	sign = 1;
	result = 0;
	while (str[i] == ' ' || (str[i] >= 9 && str[i] <= 13))
		i++;
	while (str[i] == '+' || str[i] == '-')
	{
		if (str[i] == '-')
			sign = -sign;
		i++;
	}
	while (str[i] >= '0' && str[i] <= '9')
	{
		result = result * 10 + (str[i] - '0');
		i++;
	}
	return (result * sign);
}

Tres fases claras: saltar blancos (el espacio 32 y los controles 9–13, que es lo que reconoce isspace), procesar los signos acumulando en sign (cada - lo invierte), y acumular dígitos con result = result * 10 + dígito. Con la entrada " ---+--+1234ab567" hay cinco - (impar) → negativo, y la lectura para en la a: sale -1234.

Concepto — acumular por posición. El corazón, result * 10 + dígito, es la notación posicional en base 10: cada dígito nuevo empuja los anteriores una posición a la izquierda (multiplicar por 10) y se suma el actual. Cambia el 10 por otra base y tienes ex05. Este patrón de «desplazar y sumar» es la máquina universal de leer números.

ex04ft_putnbr_base

Prototipo: void ft_putnbr_base(int nbr, char *base)Autorizada: write

Imprimir nbr en la base descrita por la cadena base, que enumera sus símbolos ("01" = binario, "0123456789ABCDEF" = hexadecimal…). Si la base es inválida —menos de 2 símbolos, con repetidos, o con +/-— no se imprime nada.

static int	ft_base_ok(char *base)
{
	int	i;
	int	j;

	i = 0;
	while (base[i])
	{
		if (base[i] == '+' || base[i] == '-')
			return (0);
		j = i + 1;
		while (base[j])
		{
			if (base[i] == base[j])
				return (0);
			j++;
		}
		i++;
	}
	if (i < 2)
		return (0);
	return (1);
}

static void	ft_put_base(long n, char *base, int len)
{
	if (n >= len)
		ft_put_base(n / len, base, len);
	write(1, &base[n % len], 1);
}

void	ft_putnbr_base(int nbr, char *base)
{
	long	n;
	int		len;

	if (!ft_base_ok(base))
		return ;
	len = ft_baselen(base);
	n = nbr;
	if (n < 0)
	{
		write(1, "-", 1);
		n = -n;
	}
	ft_put_base(n, base, len);
}

Primero se valida la base: rechaza signos, duplicados y longitudes menores que 2. La impresión es la misma recursión que ft_putnbr, pero generalizada: en vez de dividir entre 10 se divide entre len (el número de símbolos), y en vez de + '0' se indexa base[n % len]. El paso a long vuelve a estar por INT_MIN. (ft_baselen, omitida aquí, solo cuenta símbolos de la base.)

Concepto — la base es un parámetro, no una constante. Descubrir que imprimir en decimal, binario o hex es el mismo algoritmo con distinto divisor es una pequeña revelación: la base 10 no tiene nada de especial para la máquina, es una elección humana. Validar la entrada (bases con símbolos repetidos no definen una numeración) enseña además a no fiarse jamás de lo que te pasan.

ex05ft_atoi_base

Prototipo: int ft_atoi_base(char *str, char *base)

Como ft_atoi, pero leyendo str en la base dada. Si la base es inválida —menos de 2 símbolos, repetidos, o con +, - o espacios— devuelve 0.

static int	ft_index(char c, char *base)
{
	int	i;

	i = 0;
	while (base[i])
	{
		if (base[i] == c)
			return (i);
		i++;
	}
	return (-1);
}

static int	ft_convert(char *str, char *base, int len)
{
	int	i;
	int	sign;
	int	result;

	i = 0;
	sign = 1;
	result = 0;
	while (str[i] == ' ' || (str[i] >= 9 && str[i] <= 13))
		i++;
	while (str[i] == '+' || str[i] == '-')
	{
		if (str[i] == '-')
			sign = -sign;
		i++;
	}
	while (ft_index(str[i], base) >= 0)
	{
		result = result * len + ft_index(str[i], base);
		i++;
	}
	return (result * sign);
}

int	ft_atoi_base(char *str, char *base)
{
	if (!ft_base_ok(base))
		return (0);
	return (ft_convert(str, base, ft_baselen(base)));
}

La estructura calca a ft_atoi (blancos, signos, dígitos), con dos cambios: el valor de un símbolo ya no es str[i] - '0' sino su posición en la base (ft_index), y la acumulación multiplica por len en vez de por 10. El bucle de dígitos se detiene en cuanto aparece un carácter que no pertenece a la base (ft_index devuelve −1). Aquí la base inválida también incluye espacios, porque un espacio como símbolo chocaría con el salto de blancos. (ft_base_ok y ft_baselen son las del ejercicio anterior, con el añadido del rechazo de espacios.)

Concepto — el símbolo y su valor. En hex, 'F' «vale» 15 porque ocupa la posición 15 de "0123456789ABCDEF". Separar el glifo (lo que se escribe) de su valor (lo que representa) mediante una tabla de posiciones es una idea que reaparece por todas partes: codificaciones, tokenizadores, intérpretes. ft_atoi_base es su forma más pequeña y honesta.
