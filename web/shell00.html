ex00Z

Entregable: z«Solo quienes dominan lo básico saben mostrar una Z»

Crear un archivo z tal que cat z muestre Z y un salto de línea.

$ printf 'Z\n' > z

El archivo contiene exactamente dos bytes: Z (0x5A) y \n (0x0A). Parece una tontería, pero ya obliga a entender qué es un archivo (una secuencia de bytes, sin magia), qué hace cat (volcarlos a la salida estándar) y que el salto de línea final es un byte más — la Moulinette distingue un archivo de 1 byte de uno de 2.

ex01testShell00

Entregable: testShell00.tar

Crear un archivo testShell00 cuyo ls -l sea exactamente:

-r--r-xr-x 1 XX XX 40 Jun 1 23:42 testShell00

y empaquetarlo con tar -cf testShell00.tar testShell00. Tres cosas que clavar:

$ printf '%040d' 0 > testShell00    # 40 bytes exactos
$ chmod 455 testShell00             # -r--r-xr-x
$ touch -t 06012342 testShell00     # Jun 1, 23:42
$ tar -cf testShell00.tar testShell00
  • Tamaño (40): cualquier contenido vale mientras ocupe 40 bytes.
  • Permisos: -r--r-xr-x en octal es 455 (r=4, w=2, x=1 por cada tercio: propietario r--=4, grupo r-x=5, resto r-x=5).
  • Fecha: touch -t MMDDhhmm falsifica la fecha de modificación. El 23:42 no es casual: en 42 casi todas las horas de ejemplo son las 4:2 o las 23:42.

El tar conserva permisos y fechas en sus cabeceras, así que el evaluador puede comprobar todo sin extraer siquiera: tar -tvf testShell00.tar.

ex02Pues toma dos tazas

Entregable: exo2.tar

Reproducir exactamente este listado y empaquetarlo (tar -cf exo2.tar *):

drwx--xr-x 2 XX XX XX Jun 1 20:47 test0
-rwx--xr-- 1 XX XX  4 Jun 1 21:46 test1
dr-x---r-- 2 XX XX XX Jun 1 22:45 test2
-r-----r-- 2 XX XX  1 Jun 1 23:44 test3
-rw-r----x 1 XX XX  2 Jun 1 23:43 test4
-r-----r-- 2 XX XX  1 Jun 1 23:44 test5
lrwxrwxrwx 1 XX XX  5 Jun 1 22:20 test6 -> test0
$ mkdir test0 test2
$ printf 'abc\n' > test1          # 4 bytes
$ printf '1' > test3              # 1 byte
$ printf '2\n' > test4            # 2 bytes
$ ln test3 test5                  # hard link
$ ln -s test0 test6               # symlink
$ chmod 715 test0; chmod 714 test1; chmod 504 test2
$ chmod 404 test3; chmod 641 test4
$ touch -t 06012047 test0; touch -t 06012146 test1
$ touch -t 06012245 test2; touch -t 06012344 test3 test5
$ touch -t 06012343 test4; touch -h -t 06012220 test6
$ tar -cf exo2.tar *

La trampa del ejercicio está en la segunda columna: test3 y test5 marcan 2 enlaces y comparten tamaño, permisos y fecha. No son dos archivos: son el mismo inodo con dos nombres (ln sin -s). Al hacer chmod o touch sobre uno, el otro "cambia" también — porque no hay otro. test6 en cambio es un enlace simbólico: un archivo distinto cuyo contenido es la ruta test0 (por eso su tamaño es 5, los 5 caracteres de "test0", y sus permisos son siempre rwxrwxrwx). Detalle fino: la fecha del symlink se cambia con touch -h, porque touch a secas seguiría el enlace y tocaría test0.

El título — Del refrán español «¿No querías caldo? Pues toma dos tazas»: pediste aprender permisos y aquí tienes siete archivos de golpe, con hard links de regalo.

ex03¡Conéctame por SSH!

Entregable: id_ed25519_pub
$ ssh-keygen -t ed25519
$ cp ~/.ssh/id_ed25519.pub ex03/id_ed25519_pub

Generar un par de claves SSH con el algoritmo ed25519 (curva elíptica moderna: claves cortas, rápidas y sin las dudas históricas de RSA). El ejercicio tiene una función muy práctica: la clave pública se sube a la intra y es la que te permite hacer git push a Vogsphere el resto de la piscine. Quien no entiende este ejercicio no entrega nada más.

La lección real está en la advertencia del enunciado: entender la diferencia entre la clave pública (se comparte, cifra/verifica) y la privada (no sale de tu máquina jamás). Entregar la privada por error es el clásico suspenso doloroso — de ahí que el archivo pedido se llame explícitamente id_ed25519_pub: "el nombre del archivo no fue elegido al azar".

ex04midLS

Entregable: midLS

Un archivo con el comando que lista el directorio actual: sin ocultos, ordenado por fecha de modificación, separado por coma y espacio, y con / al final de los directorios.

ls -tpm

Tres flags hacen todo el trabajo — el ejercicio es un RTFM (Read The F… Manual) puro:

  • -t — ordena por fecha de modificación (más reciente primero).
  • -p — añade / a los directorios.
  • -m — salida "stream": entradas separadas por , .

Los ocultos ya quedan fuera por defecto (eso es -a, que precisamente no se pasa). La gracia de midLS es descubrir que ls tiene ~60 opciones y que la respuesta a "¿cómo hago X?" casi siempre está en man ls, no en escribir un script.

ex05Git commit

Entregable: git_commit.sh

Script que muestra los hashes de los últimos 5 commits del repositorio.

git log -5 --format=%H

git log con --format=%H imprime solo el hash completo de cada commit (sin autor, fecha ni mensaje), y -5 corta en cinco. El enunciado enseña la salida pasada por cat -e (que marca los finales de línea con $) para dejar claro que no puede haber espacios ni líneas extra: la Moulinette compara la salida literal.

ex06gitignore

Entregable: git_ignore.sh

Script que lista los archivos ignorados por el repositorio git actual.

git ls-files --others --ignored --exclude-standard

Descomponiendo: ls-files es el comando de "fontanería" (plumbing) de git para consultar su índice; --others pide archivos no rastreados; --ignored los filtra a los que casan con alguna regla de ignorado; y --exclude-standard hace que esas reglas sean las estándar (.gitignore, .git/info/exclude, config global). La pareja ex05/ex06 tiene el mismo mensaje: git no es solo add/commit/push, tiene una API de consulta enorme.

ex07diff

Entregable: bMaterial: a, sw.diff

El proyecto da un archivo a — el texto de apertura de Star Wars: Episodio IV — y un sw.diff. Hay que crear b tal que diff a b produzca exactamente ese sw.diff. La pista del enunciado (man patch) lo dice todo:

$ cp a b
$ patch b < sw.diff

Un diff no es una descripción: es un programa de edición que patch sabe ejecutar. Aplicado sobre la copia de a, produce el b buscado — y se verifica cerrando el círculo: diff a b regenera un diff idéntico al original. Así funcionan por dentro los parches de kernel, los pull requests y el propio git.

El texto — El diff convierte el opening crawl en una versión corrupta: "Episode V, A NEW H0PE", la DEATH STAR pasa a ser "STAR DEATH", la princesa Leia es "Princess Mehdi" (guiño a algún staff de 42) y en vez de restaurar la libertad en la galaxia, restaura "la dictadura". Vándalos.

ex08clean

Entregable: cleanUn solo comando, sin ; ni &&

Buscar en el directorio actual y subdirectorios los archivos que terminan en ~ o que empiezan y terminan con #, mostrarlos y borrarlos.

find . -type f \( -name "*~" -o -name "#*#" \) -print -delete
  • \( … -o … \) — agrupación con OR; los paréntesis se escapan para que no los interprete el shell.
  • -print -delete — las "acciones" de find se encadenan en orden: primero imprime, luego borra. Por eso no hace falta ; — find ya es un lenguaje en sí mismo, esa es la lección.

Los patrones no son arbitrarios: archivo~ y #archivo# son los backups y autosaves que va dejando Emacs — el ejercicio es, literalmente, limpiar la basura del editor.

ex09Son ilusiones, no trucos, Michael…

Entregable: ft_magic

Crear un archivo mágico para que file detecte como "42 file" los archivos que contienen la cadena 42 en el byte 42.

42	string	42	42 file

¿Cómo sabe file que algo es un PNG, un PDF o un ELF sin mirar la extensión? Consultando una base de datos de "números mágicos": patrones de bytes en posiciones fijas (un PNG empieza por \x89PNG, un ELF por \x7fELF…). El formato de esa base de datos (man 5 magic) es: offset, tipo, valor, mensaje. Nuestra línea dice: en el offset 42, si hay la cadena "42", el archivo es un "42 file".

$ printf '%042d42' 0 > f42     # "42" en el byte 42
$ file -m ft_magic f42
f42: 42 file
El título — Cita de Arrested Development: GOB Bluth, mago fracasado, corrige indignado a su hermano cada vez que llama "trucos" a sus ilusiones. Aplica: la detección de tipos de archivo parece magia y es solo mirar bytes en el sitio justo.
