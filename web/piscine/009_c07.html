C Piscine — C 07

El módulo de la memoria dinámica: por primera vez tus funciones reservan memoria con malloc y devuelven arrays y cadenas de tamaño desconocido en tiempo de compilación. Duplicar cadenas, generar rangos, unir, convertir bases y partir por separadores.

  • ex01 — ft_range
  • ex02 — ft_ultimate_range
  • ex03 — ft_strjoin

El concepto que vertebra el módulo: el heap, malloc y el ownership — Hasta ahora toda tu memoria era automática: variables locales y arrays de tamaño fijo que viven en la pila (stack) y desaparecen solos al salir de la función. El problema: una función no puede devolver un array local, porque al terminar ese array ya no existe — devolverías la dirección de memoria basura. Cuando el tamaño se decide en ejecución (¿cuántos enteros hay entre min y max? ¿cuántas palabras tiene esta cadena?) necesitas otra región: el heap (montón). malloc(n) te reserva n bytes del heap y te devuelve su dirección; esa memoria vive hasta que tú la liberas con free. De ahí nacen las dos reglas que este módulo te mete en el cuerpo. Primera: reservas el tamaño exacto, y por eso escribes malloc(sizeof(int) * n) o sizeof(char) * (len + 1) — el +1 es para el '\0' que cierra toda cadena, y sizeof pregunta al compilador cuánto ocupa cada elemento en esta máquina en vez de asumir 4 u 8. Segunda: el ownership (propiedad). Cuando una función devuelve memoria del heap, el que la llama hereda la obligación de liberarla; si nadie lo hace, esa memoria queda reservada para siempre y tienes una fuga (memory leak). Los tests de este módulo comprueban tanto el contenido como que todo lo que reservas se pueda free-ar. ex00ft_strdup

Entrega: ft_strdup.cAutorizado: malloc

Reproducir strdup: reservar una cadena nueva y copiar en ella src, devolviendo la copia.

char	*ft_strdup(char *src)
{
	char	*dst;
	int		i;

	dst = (char *)malloc(sizeof(char) * (ft_strlen(src) + 1));
	if (!dst)
		return (NULL);
	i = 0;
	while (src[i])
	{
		dst[i] = src[i];
		i++;
	}
	dst[i] = '\0';
	return (dst);
}

Tres pasos que se repetirán todo el módulo: medir (ft_strlen), reservar el tamaño justo (+1 para el terminador), copiar y cerrar con '\0'. Y siempre, comprobar que malloc no devolvió NULL antes de escribir.

Qué te obliga a aprender — El ciclo de vida de una cadena en el heap y por qué no basta con dst = src: eso copiaría el puntero (dos nombres para los mismos bytes), no el contenido. Duplicar significa pedir memoria propia y copiar byte a byte. Es el "hola mundo" de la gestión de memoria: si esto lo tienes claro, el resto del módulo son variaciones.

ex01ft_range

Entrega: ft_range.cAutorizado: malloc

Devolver un array con todos los enteros de min a max, incluyendo min y excluyendo max. Si min >= max, devolver NULL.

int	*ft_range(int min, int max)
{
	int	*arr;
	int	i;
	int	size;

	if (min >= max)
		return (NULL);
	size = max - min;
	arr = (int *)malloc(sizeof(int) * size);
	if (!arr)
		return (NULL);
	i = 0;
	while (i < size)
	{
		arr[i] = min + i;
		i++;
	}
	return (arr);
}

El tamaño se calcula: max - min elementos. Al ser un array de enteros, se reserva sizeof(int) * size — no size a secas: cada int ocupa varios bytes.

Qué te obliga a aprender — Que devolver un array desde una función exige heap: un int arr[size] local moriría al volver. Y que el tamaño de la reserva se cuenta en bytes, de ahí sizeof(int). También el contrato de errores: ante entrada inválida (min >= max) devuelves NULL, y quien te llama tendrá que comprobarlo antes de usar el resultado — el mismo patrón que malloc usa contigo.

ex02ft_ultimate_range

Entrega: ft_ultimate_range.cAutorizado: malloc

Igual que ex01 pero el array se devuelve por parámetro (int **range) y la función devuelve el tamaño, o -1 si falla el malloc. Si min >= max, deja *range en NULL y devuelve 0.

int	ft_ultimate_range(int **range, int min, int max)
{
	int	i;
	int	size;

	if (min >= max)
	{
		*range = NULL;
		return (0);
	}
	size = max - min;
	*range = (int *)malloc(sizeof(int) * size);
	if (!*range)
		return (-1);
	i = 0;
	while (i < size)
	{
		(*range)[i] = min + i;
		i++;
	}
	return (size);
}

El doble puntero int **range es la clave: el llamador pasa la dirección de su propio puntero, y la función escribe en él con *range = …. Así la función devuelve dos cosas: el array (por el parámetro) y el tamaño (por el return). Ojo a los paréntesis en (*range)[i]: primero se deshace un nivel de indirección, luego se indexa.

Qué te obliga a aprender — El idioma clásico de C para "devolver varias cosas": una por return y las demás por punteros de salida — aquí llevado a un doble puntero porque lo que se rellena es, a su vez, un puntero. Es exactamente el patrón de ft_div_mod de C01, pero con memoria dinámica de por medio. Entender (*range)[i] frente a *range[i] (que significaría otra cosa por la precedencia) es la clase de detalle de punteros que separa "compila por suerte" de "sé lo que escribo".

ex03ft_strjoin

Entrega: ft_strjoin.cAutorizado: malloc

Concatenar las size cadenas de strs usando sep entre ellas. Si size == 0, devolver una cadena vacía que se pueda free-ar.

char	*ft_strjoin(int size, char **strs, char *sep)
{
	char	*res;
	char	*p;
	int		i;

	res = (char *)malloc(sizeof(char) * (total_len(size, strs, sep) + 1));
	if (!res)
		return (NULL);
	p = res;
	i = 0;
	while (i < size)
	{
		p = ft_append(p, strs[i]);
		if (i < size - 1)
			p = ft_append(p, sep);
		i++;
	}
	*p = '\0';
	return (res);
}

Primero se calcula el tamaño total (suma de las longitudes más la del separador size - 1 veces), se reserva de una vez, y luego se va copiando. El helper ft_append copia una cadena y devuelve el puntero justo detrás de lo escrito, para que la siguiente copia continúe donde acabó la anterior. El separador se pone entre elementos, nunca después del último (de ahí if (i < size - 1)).

Qué te obliga a aprender — La estrategia "medir primero, reservar una vez, llenar después", que evita reservar y re-reservar en cada paso. Y el detalle exigido: con size == 0 no devuelves NULL sino "" — una cadena de un solo byte ('\0') reservada en el heap. Esa distinción entre "no hay resultado" (NULL) y "el resultado es vacío pero existe y hay que liberarlo" es sutil y muy real: media librería estándar depende de tratarla bien.

ex04ft_convert_base

Entrega: ft_convert_base.c, ft_convert_base2.cAutorizado: malloc, free

Convertir la cadena nbr, escrita en base_from, a su representación en base_to. Cualquier base inválida ⇒ NULL. Se respetan las reglas de atoi_base: espacios iniciales, varios signos +/-, y solo un - como prefijo del resultado.

/* validación de base: longitud >= 2, sin repetidos,
   sin '+', '-' ni espacios */
int	ft_is_valid_base(char *base);

/* núcleo del pipeline */
char	*ft_convert_base(char *nbr, char *base_from, char *base_to)
{
	long	value;

	if (!ft_is_valid_base(base_from) || !ft_is_valid_base(base_to))
		return (NULL);
	value = ft_atoi_base(nbr, base_from);
	return (fill_result(value, base_to, ft_baselen(base_to)));
}

El problema se parte en dos mitades limpias: leer y escribir. ft_atoi_base lee la cadena en base_from y produce un long (saltando espacios, aplicando todos los signos, acumulando valor · base + dígito). fill_result hace lo inverso: toma el número y genera la cadena en base_to dividiendo repetidamente entre el tamaño de la base, y antepone un único - si es negativo. El módulo obliga a dos archivos porque no cabe todo en cinco funciones por fichero: los helpers de validación y lectura viven en ft_convert_base2.c y se declaran como prototipos en el principal.

Qué te obliga a aprender — Que "convertir de base" no es una operación: son dos, con un entero como puente. Un número no "está en base 10"; está en la máquina como bits, y las bases solo son formas de escribirlo. Separar el parser (texto→entero) del formateador (entero→texto) es el mismo diseño que hay detrás de printf, scanf y cualquier serializador. Además concentra las trampas de robustez de toda la piscine: bases con caracteres repetidos o prohibidos, signos múltiples, el prefijo con un solo -, y usar long para que el acumulador no se desborde al leer. Y es tu primer proyecto multi-archivo: aprender a declarar prototipos para compartir funciones entre .c sin un .h.

ex05ft_split

Entrega: ft_split.cAutorizado: malloc

Partir str en palabras, tratando cada carácter de charset como separador. Devolver un array de cadenas terminado en NULL, sin cadenas vacías y sin modificar str.

char	**ft_split(char *str, char *charset)
{
	char	**result;

	result = (char **)malloc(sizeof(char *) * (count_words(str, charset) + 1));
	if (!result)
		return (NULL);
	return (fill_words(result, str, charset));
}

Dos pasadas. La primera, count_words, cuenta cuántas palabras hay para reservar el array de punteros justo (más 1 para el NULL final). La segunda, fill_words, localiza cada palabra entre separadores y la duplica con word_dup (un strdup acotado a [inicio, fin)). La regla "sin cadenas vacías" sale sola de tratar cualquier racha de separadores consecutivos como un único corte: solo se crea palabra cuando hay al menos un carácter no separador.

Qué te obliga a aprender — El ejercicio cumbre del módulo: memoria dinámica de dos niveles. Reservas un array de punteros (char **) y, para cada casilla, reservas otra cadena (char *) — memoria que apunta a memoria. Y con ello, el ownership completo: quien recibe el resultado debe liberar primero cada palabra y luego el array. El centinela NULL al final es lo que permite recorrerlo sin saber su tamaño (while (result[i])), la misma convención que el '\0' de las cadenas pero un nivel más arriba. Contar antes de reservar, tratar los separadores consecutivos, respetar la cadena de entrada: es el ejercicio donde todo C07 (medir, reservar el tamaño exacto, copiar, no fugar) se junta.
