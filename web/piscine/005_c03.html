C Piscine — C 03

Comparar y concatenar cadenas. Se reimplementan strcmp, strncmp, strcat, strncat, strstr y strlcat. 6 ejercicios (ex00–ex05); todos con funciones autorizadas: ninguna.

El contrato de strcmp — El hilo conductor del módulo. Comparar dos cadenas no es «¿son iguales?» sino «¿cuál va antes?». El contrato de la libc es preciso: se recorren ambas byte a byte hasta el primer par que difiere, y se devuelve la resta de esos dos bytes (interpretados como unsigned char). El signo del resultado es lo único que importa: negativo si s1 va antes, positivo si va después, 0 si son idénticas. De ahí sale el orden lexicográfico —el del diccionario, pero según ASCII— sobre el que se construyen sort, los índices y media informática. Todo el módulo gira en torno a leer dos punteros en paralelo y decidir con el primer byte que no coincide.

ex00ft_strcmp

Prototipo: int ft_strcmp(char *s1, char *s2)

Reproducir strcmp: comparar dos cadenas y devolver un entero negativo, cero o positivo.

int	ft_strcmp(char *s1, char *s2)
{
	int	i;

	i = 0;
	while (s1[i] && s1[i] == s2[i])
		i++;
	return ((unsigned char)s1[i] - (unsigned char)s2[i]);
}

El bucle avanza mientras no se acabe s1 y los caracteres coincidan. Se para en dos casos: se encontró una diferencia, o se llegó al final de s1. En ambos, la resta s1[i] - s2[i] da la respuesta correcta: si son iguales hasta el \0 de las dos, esa resta es 0. El casting a unsigned char es parte del contrato: garantiza que la comparación trate los bytes como 0–255, igual que la strcmp real.

Concepto — ¿por qué unsigned char?. En muchos sistemas char es con signo, así que un byte > 127 valdría negativo. Sin el cast, comparar un carácter «normal» con uno acentuado o binario daría un signo equivocado y el orden saldría del revés. Es un detalle diminuto que separa una strcmp «que parece funcionar» de una correcta: la Moulinette prueba exactamente estos bordes.

ex01ft_strncmp

Prototipo: int ft_strncmp(char *s1, char *s2, unsigned int n)

Como strcmp pero comparando a lo sumo n caracteres.

int	ft_strncmp(char *s1, char *s2, unsigned int n)
{
	unsigned int	i;

	if (n == 0)
		return (0);
	i = 0;
	while (i < n - 1 && s1[i] && s1[i] == s2[i])
		i++;
	return ((unsigned char)s1[i] - (unsigned char)s2[i]);
}

La guarda n == 0 al principio no es opcional: como n es unsigned, escribir n - 1 con n = 0 no da −1, sino 4294967295 (envuelve por abajo), y el bucle recorrería memoria hasta petar. Con esa comparación cubierta, el bucle avanza hasta n − 1 y compara ahí el último par.

Concepto — el underflow de los sin signo. Los unsigned no tienen números negativos: al bajar de 0 dan la vuelta al valor máximo. Es la misma trampa que aparece en bucles while (i >= 0) con i sin signo (nunca terminan). Aprender a desconfiar de las restas sobre unsigned es una de las lecciones duraderas de este ejercicio.

ex02ft_strcat

Prototipo: char *ft_strcat(char *dest, char *src)

Pegar src al final de dest y devolver dest.

char	*ft_strcat(char *dest, char *src)
{
	int	i;
	int	j;

	i = 0;
	while (dest[i])
		i++;
	j = 0;
	while (src[j])
	{
		dest[i + j] = src[j];
		j++;
	}
	dest[i + j] = '\0';
	return (dest);
}

Dos fases: primero i se planta en el \0 de dest (su longitud), y luego se copia src a partir de ahí, en dest[i + j]. Al acabar hay que volver a poner el terminador, porque hemos sobrescrito el que tenía dest.

Concepto — quien concatena, confía. strcat asume que dest tiene sitio de sobra para lo que le pegas. No hay comprobación de tamaño: si no cabe, escribes fuera del búfer. Es el mismo pecado original que strcpy, y la razón de que exista strlcat (ex05). Verlo aquí en su versión «ingenua» hace que la «segura» del final del módulo tenga sentido.

ex03ft_strncat

Prototipo: char *ft_strncat(char *dest, char *src, unsigned int nb)

Concatenar como mucho nb caracteres de src.

char	*ft_strncat(char *dest, char *src, unsigned int nb)
{
	unsigned int	i;
	unsigned int	j;

	i = 0;
	while (dest[i])
		i++;
	j = 0;
	while (j < nb && src[j])
	{
		dest[i + j] = src[j];
		j++;
	}
	dest[i + j] = '\0';
	return (dest);
}

Idéntico a strcat salvo la guarda extra j < nb en el segundo bucle. A diferencia de strncpy, aquí strncat sí añade siempre el \0 final: es un detalle de la especificación que conviene recordar de memoria.

Concepto — familias n. Las variantes con n (strncpy, strncmp, strncat) acotan cuántos bytes tocan, pero cada una decide de forma distinta qué hacer con el terminador. No hay una regla uniforme: hay que leer el man de cada una. Descubrir esas asimetrías es parte del oficio.

ex04ft_strstr

Prototipo: char *ft_strstr(char *str, char *to_find)

Buscar la primera aparición de to_find dentro de str y devolver un puntero a ella (o NULL si no está). Si to_find es vacío, devolver str.

char	*ft_strstr(char *str, char *to_find)
{
	int	i;
	int	j;

	if (!to_find[0])
		return (str);
	i = 0;
	while (str[i])
	{
		j = 0;
		while (str[i + j] && str[i + j] == to_find[j])
			j++;
		if (!to_find[j])
			return (str + i);
		i++;
	}
	return (0);
}

Es una búsqueda de doble bucle: por cada posición i de str, el bucle interno intenta casar to_find carácter a carácter. Si el interno llega al \0 de to_find (!to_find[j]), significa que casó entero, y se devuelve el puntero al inicio de la coincidencia, str + i.

Concepto — el primer algoritmo «de verdad». Hasta aquí todo eran recorridos lineales; strstr es coincidencia de patrones (pattern matching) en su forma más directa, O(n·m). Los algoritmos serios de búsqueda (KMP, Boyer–Moore) optimizan justamente este doble bucle. Antes de mejorar algo, hay que saber escribir la versión honesta: eso es este ejercicio.

ex05ft_strlcat

Prototipo: unsigned int ft_strlcat(char *dest, char *src, unsigned int size)

La concatenación «segura» de BSD. Añade src a dest sin pasarse de size, termina siempre en \0, y devuelve la longitud que habría tenido el resultado (útil para detectar truncamiento).

unsigned int	ft_strlcat(char *dest, char *src, unsigned int size)
{
	unsigned int	dlen;
	unsigned int	slen;
	unsigned int	i;

	dlen = 0;
	while (dest[dlen] && dlen < size)
		dlen++;
	slen = 0;
	while (src[slen])
		slen++;
	if (dlen == size)
		return (size + slen);
	i = 0;
	while (src[i] && dlen + i + 1 < size)
	{
		dest[dlen + i] = src[i];
		i++;
	}
	dest[dlen + i] = '\0';
	return (dlen + slen);
}

Primero se mide dest pero sin pasar de size: si dest no tiene \0 dentro del búfer, se considera «lleno» y se devuelve size + slen sin copiar nada. Si hay sitio, se anexa dejando hueco para el terminador (dlen + i + 1 < size). El valor devuelto es dlen + slen: la longitud ideal, la haya cabido o no.

Concepto — informar del truncamiento. La gracia de strlcat sobre strncat es su valor de retorno: comparándolo con size, quien llama sabe si se perdieron datos y puede reservar un búfer mayor y reintentar. Es un patrón de diseño de API —«di siempre cuánto habrías necesitado»— que reaparece en muchas funciones de sistema (snprintf, read…).
