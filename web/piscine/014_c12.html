C Piscine — C 12

Listas enlazadas: la primera estructura de datos que se construye a mano, nodo a nodo, con malloc. Dieciocho ejercicios que van del elemento suelto a listas ordenadas que se fusionan sin duplicar memoria — y que introducen el puntero a puntero (t_list **) para poder cambiar la cabeza desde dentro.

La estructura que se repite en todo el módulo — Todos los ejercicios usan el mismo nodo, entregado en ft_list.h: 
typedef struct s_list
{
	struct s_list	*next;
	void			*data;
}	t_list;
Dos ideas clave. El nodo se apunta a sí mismo (struct s_list *next): esa recursividad en el tipo es la que encadena la lista. Y void *data: un puntero «a cualquier cosa», que permite que la misma lista guarde enteros, cadenas o structs. La lista es genérica porque no sabe qué guarda.

ex00ft_create_elem

Entregable: ft_create_elem.c, ft_list.hAutorizadas: malloc

Crear un nodo: reservar memoria, poner su data y dejar next a NULL.

elem = malloc(sizeof(t_list));
if (!elem)
	return (NULL);
elem->data = data;
elem->next = NULL;
return (elem);
Qué te obliga a aprender — El ladrillo de todo lo demás. Un nodo vive en el heap (por eso malloc): sobrevive a la función que lo crea, al revés que una variable local. Dejar next a NULL no es un detalle: es la invariante de que un nodo recién nacido no apunta a basura. Toda la piscina de listas se apoya en que esta función sea impecable.

ex01ft_list_push_front

Entregable: ft_list_push_front.c, ft_list.hAutorizadas: ft_create_elem

Añadir un elemento al principio y actualizar la cabeza.

void	ft_list_push_front(t_list **begin_list, void *data)
{
	t_list	*elem;

	elem = ft_create_elem(data);
	if (!elem)
		return ;
	elem->next = *begin_list;
	*begin_list = elem;
}
Qué te obliga a aprender — Aquí aparece el t_list ** y es el concepto más difícil del módulo. Para cambiar a dónde apunta la cabeza del llamante, no basta con recibir la cabeza: hay que recibir la dirección de la variable cabeza. Con un solo * cambiarías una copia y el llamante no se enteraría. El doble puntero es «pásame dónde vive tu puntero para que yo lo reescriba».

ex02ft_list_size

Entregable: ft_list_size.c, ft_list.hAutorizadas: ninguna

Contar los elementos.

size = 0;
while (begin_list)
{
	size++;
	begin_list = begin_list->next;
}
return (size);
Qué te obliga a aprender — El recorrido canónico de una lista: avanzar p = p->next hasta caer en NULL. Como begin_list es una copia local del puntero, puedes machacarla sin dañar la lista: mueves la vista, no los nodos. Ese bucle while (p) es el for de las listas.

ex03ft_list_last

Entregable: ft_list_last.c, ft_list.hAutorizadas: ninguna

Devolver el último nodo.

while (begin_list->next)
	begin_list = begin_list->next;
return (begin_list);
Qué te obliga a aprender — La diferencia entre parar en next == NULL (el último nodo) y parar en el nodo mismo == NULL (te has pasado). Aquí se para en begin_list->next. Y el caso borde: una lista vacía no tiene último, hay que devolver NULL sin desreferenciar. Este «buscar el final» es lo que hace lento el push_back ingenuo.

ex04ft_list_push_back

Entregable: ft_list_push_back.c, ft_list.hAutorizadas: ft_create_elem

Añadir al final. Si la lista está vacía, el nuevo nodo pasa a ser la cabeza.

if (!*begin_list)
{
	*begin_list = elem;
	return ;
}
last = *begin_list;
while (last->next)
	last = last->next;
last->next = elem;
Qué te obliga a aprender — Que la lista simplemente enlazada es asimétrica: meter por delante es O(1), meter por detrás es O(n) porque hay que recorrerla entera. Y otra vez el doble puntero, pero solo se usa de verdad en el caso de lista vacía (cuando hay que crear la cabeza); si ya hay nodos, el enganche es sobre last->next. Distinguir esos dos casos es el ejercicio.

ex05ft_list_push_strs

Entregable: ft_list_push_strs.c, ft_list.hAutorizadas: ft_create_elem

Construir una lista con las cadenas de strs. El primer elemento de la tabla acaba al final de la lista; se devuelve la cabeza.

i = 0;
while (i < size)
{
	elem = ft_create_elem(strs[i]);
	elem->next = list;   /* push_front manual */
	list = elem;
	i++;
}
return (list);
Qué te obliga a aprender — Que insertar por delante invierte el orden: metes strs[0] primero y queda al fondo; strs[size-1] entra el último y queda en cabeza. Entender esa inversión es el ejercicio, y es la misma razón por la que una pila (LIFO) devuelve las cosas del revés.

ex06ft_list_clear

Entregable: ft_list_clear.c, ft_list.hAutorizadas: free

Liberar todos los nodos y, con free_fct, también sus data.

while (begin_list)
{
	tmp = begin_list->next;
	free_fct(begin_list->data);
	free(begin_list);
	begin_list = tmp;
}
Qué te obliga a aprender — El error clásico de C: free(p); p = p->next; lee memoria ya liberada (use-after-free). Por eso hay que guardar next en tmp antes de liberar. Y la doble propiedad: el nodo lo liberas tú con free, pero el data lo libera free_fct — porque quien creó el dato sabe cómo destruirlo, y la lista no.

ex07ft_list_at

Entregable: ft_list_at.c, ft_list.hAutorizadas: ninguna

Devolver el nodo n-ésimo (el primero es el 0), o NULL si no existe.

i = 0;
while (begin_list)
{
	if (i == nbr)
		return (begin_list);
	i++;
	begin_list = begin_list->next;
}
return (NULL);
Qué te obliga a aprender — Que en una lista no hay acceso directo: llegar al elemento 5 cuesta cinco saltos, no un cálculo de dirección como en un array (tab[5]). Ese es el gran trade-off de las listas frente a los arrays: baratas para insertar/borrar en cualquier punto, caras para acceder por índice.

ex08ft_list_reverse

Entregable: ft_list_reverse.cAutorizadas: ninguna

Invertir el orden de los nodos. Ojo: este ejercicio entrega solo el .c (usa el ft_list.h del corrector).

prev = NULL;
cur = *begin_list;
while (cur)
{
	next = cur->next;
	cur->next = prev;
	prev = cur;
	cur = next;
}
*begin_list = prev;
Qué te obliga a aprender — El baile de tres punteros (prev, cur, next) que da la vuelta a los enlaces sin perder el resto de la lista. Si le das la vuelta a cur->next sin haber guardado antes next, pierdes la cola. Es una de esas piezas que hay que dibujar en papel una vez y ya no se olvida. Se hace en una pasada, O(n), sin memoria extra.

ex09ft_list_foreach

Entregable: ft_list_foreach.c, ft_list.hAutorizadas: ninguna

Aplicar f al data de cada nodo, en orden.

while (begin_list)
{
	f(begin_list->data);
	begin_list = begin_list->next;
}
Qué te obliga a aprender — El ft_foreach de C 11, pero sobre una lista en vez de un array. Junta las dos ideas del bloque de C: puntero a función (el qué) y recorrido de lista (el cómo). A partir de aquí, casi todo lo que queda es este bucle con una condición o una acción distinta.

ex10ft_list_foreach_if

Entregable: ft_list_foreach_if.c, ft_list.hAutorizadas: ninguna

Como foreach, pero solo aplica f donde cmp(data, data_ref) devuelva 0.

while (begin_list)
{
	if (cmp(begin_list->data, data_ref) == 0)
		f(begin_list->data);
	begin_list = begin_list->next;
}
Qué te obliga a aprender — Dos funciones inyectadas a la vez: cmp decide, f actúa. Y una función con cuatro parámetros, justo el máximo que permite la Norma. Es filter + map combinados: recorre, filtra por comparación con una referencia y transforma solo lo que pasa el filtro.

ex11ft_list_find

Entregable: ft_list_find.c, ft_list.hAutorizadas: ninguna

Devolver el primer nodo cuyo data, comparado con data_ref, hace que cmp devuelva 0.

while (begin_list)
{
	if (cmp(begin_list->data, data_ref) == 0)
		return (begin_list);
	begin_list = begin_list->next;
}
return (NULL);
Qué te obliga a aprender — Búsqueda lineal con criterio genérico y cortocircuito: en cuanto encuentra, devuelve. La comparación la decide quien llama, así que la misma find localiza por igualdad exacta, por prefijo o por lo que quieras. Es el find de cualquier librería, sobre tu propia estructura.

ex12ft_list_remove_if

Entregable: ft_list_remove_if.c, ft_list.hAutorizadas: free

Borrar todos los nodos que casen con data_ref según cmp, liberando su data con free_fct.

/* 1) quitar los que casen mientras estén en la cabeza */
while (*begin_list && cmp((*begin_list)->data, data_ref) == 0)
{ ... free ... *begin_list = tmp; }
/* 2) recorrer el resto mirando cur->next */
while (cur && cur->next)
{
	if (cmp(cur->next->data, data_ref) == 0)
		{ tmp = cur->next; cur->next = tmp->next; free_fct(tmp->data); free(tmp); }
	else
		cur = cur->next;
}
Qué te obliga a aprender — El caso más traicionero de las listas: borrar mientras recorres. Hay que tratar aparte los borrados en la cabeza (mueven *begin_list, de ahí el doble puntero) y los del interior (se miran desde el nodo anterior, con cur->next). Y no avanzar cuando borras, o te saltas el siguiente. Coordinar el desenganche con el free sin dejar cabos sueltos es el examen.

ex13ft_list_merge

Entregable: ft_list_merge.c, ft_list.hAutorizadas: ninguna

Pegar begin2 al final de begin1. Sin crear nodos.

if (!*begin_list1)
{
	*begin_list1 = begin_list2;
	return ;
}
last = *begin_list1;
while (last->next)
	last = last->next;
last->next = begin_list2;
Qué te obliga a aprender — Que unir dos listas es reconectar un puntero, no copiar nada. «Sin crear elementos» es la clave: se reutilizan los nodos de begin2 tal cual, enganchando el next del último de begin1. Coste O(n) por buscar la cola, pero cero memoria nueva.

ex14ft_list_sort

Entregable: ft_list_sort.c, ft_list.hAutorizadas: ninguna

Ordenar la lista de forma creciente comparando con cmp.

if (cmp(cur->data, cur->next->data) > 0)
{
	tmp = cur->data;
	cur->data = cur->next->data;
	cur->next->data = tmp;
	cur = *begin_list;   /* vuelve al principio tras cada cambio */
}
Qué te obliga a aprender — Un truco que simplifica mucho: en vez de reencadenar nodos (mover next), se intercambian los data. La lista física no cambia; cambia qué guarda cada nodo. Es una ordenación por burbuja: correcta y fácil de razonar, aunque O(n²). El comparador genérico ordena enteros, cadenas o lo que sea.

ex15ft_list_reverse_fun

Entregable: ft_list_reverse_fun.c, ft_list.hAutorizadas: ninguna

Invertir la lista, pero recibiendo t_list * (un solo puntero, no doble).

while (i < n / 2)
{
	right = node_at(begin_list, n - 1 - i);
	tmp = left->data;         /* intercambia extremos hacia el centro */
	left->data = right->data;
	right->data = tmp;
	left = left->next;
	i++;
}
Qué te obliga a aprender — Un detalle de firma con consecuencias grandes: como recibe t_list * (no **), no puede cambiar la cabeza del llamante. Así que no vale reencadenar nodos (el primero pasaría a ser el último y el llamante se quedaría apuntando al sitio equivocado); hay que invertir los data intercambiando extremos hacia el centro. La forma de una función te dicta qué solución es legal.

ex16ft_sorted_list_insert

Entregable: ft_sorted_list_insert.c, ft_list.hAutorizadas: ft_create_elem

Insertar un nuevo elemento en su sitio de una lista ya ordenada, de modo que siga creciente.

if (!*begin_list || cmp((*begin_list)->data, data) > 0)
{ elem->next = *begin_list; *begin_list = elem; return ; }
cur = *begin_list;
while (cur->next && cmp(cur->next->data, data) <= 0)
	cur = cur->next;
elem->next = cur->next;
cur->next = elem;
Qué te obliga a aprender — Mantener una invariante: la lista está ordenada y debe seguir estándolo tras insertar. Se busca el hueco (el primer nodo mayor) y se empalma ahí. El caso de insertar en cabeza vuelve a pedir el doble puntero. Insertar así, uno a uno, es la base del insertion sort.

ex17ft_sorted_list_merge

Entregable: ft_sorted_list_merge.c, ft_list.hAutorizadas: ninguna

Fusionar begin2 (ordenada) dentro de begin1 (ordenada) manteniendo el orden creciente.

while (begin_list2)
{
	next2 = begin_list2->next;          /* guarda antes de mover el nodo */
	ins_sorted(begin_list1, begin_list2, cmp);
	begin_list2 = next2;
}
Qué te obliga a aprender — El cierre del módulo: se reutiliza la lógica de inserción ordenada (ex16) pero sin crear nodos, empalmando los de begin2 uno a uno en su sitio. Hay que guardar next2 antes de reengancharlo, porque al insertarlo su next se sobrescribe. Esta fusión de dos listas ordenadas es, en esencia, el corazón del merge sort.
