C Piscine — C 02

Manipulación de cadenas carácter a carácter. Se reimplementan trozos de la libc (strcpy, strncpy, strlcpy) y se escriben predicados y transformaciones sobre texto. 13 ejercicios (ex00–ex12); todos con funciones autorizadas: ninguna, salvo ex11 y ex12 que pueden usar write.

¿Qué es un char? — El tema de fondo de todo el módulo. Un char no es «una letra»: es un entero de 8 bits (un byte). Cuando escribes 'A', el compilador guarda el número 65; 'a' es 97, '0' es 48. Esa correspondencia es la tabla ASCII, y explica los trucos que se repiten aquí: pasar de mayúscula a minúscula es sumar 32 (la distancia entre 'A' y 'a'), y comprobar «¿es una letra?» es preguntar «¿el número cae en el rango 65–90 o 97–122?». Reimplementar la libc no es reinventar la rueda por gusto: es dejar de tratar strcpy como magia y entender que por dentro solo hay un bucle que copia bytes hasta el \0. En el examen no hay #include <string.h> que te salve.

ex00ft_strcpy

Prototipo: char *ft_strcpy(char *dest, char *src)

Copiar la cadena src dentro de dest, incluido el \0 final, y devolver dest.

char	*ft_strcpy(char *dest, char *src)
{
	int	i;

	i = 0;
	while (src[i])
	{
		dest[i] = src[i];
		i++;
	}
	dest[i] = '\0';
	return (dest);
}

El bucle avanza mientras src[i] no sea \0 (que en C vale 0, es decir falso). Al salir, src[i] es el terminador, así que hay que copiarlo a mano: sin la línea dest[i] = '\0' la copia no sería una cadena válida, solo una ristra de bytes sin final.

Concepto — el \0 no es opcional. En C una «string» no guarda su longitud en ningún sitio: es un puntero al primer carácter, y se sabe dónde acaba porque hay un byte 0. Todo el módulo depende de esta convención. Olvidar copiar el terminador es el bug clásico que hace que el siguiente printf imprima basura hasta topar con un 0 por casualidad.

ex01ft_strncpy

Prototipo: char *ft_strncpy(char *dest, char *src, unsigned int n)

Copiar como mucho n caracteres. Si src es más corto que n, el resto de dest se rellena con \0 hasta completar n.

char	*ft_strncpy(char *dest, char *src, unsigned int n)
{
	unsigned int	i;

	i = 0;
	while (i < n && src[i])
	{
		dest[i] = src[i];
		i++;
	}
	while (i < n)
	{
		dest[i] = '\0';
		i++;
	}
	return (dest);
}

Son dos bucles: el primero copia hasta que se acaba src o se llega a n; el segundo rellena con ceros lo que falte. La sutileza de strncpy —y la razón por la que es una función traicionera en la vida real— es que no garantiza terminador: si src tiene n caracteres o más, dest queda sin \0.

Concepto — el tipo importa. Aquí n es unsigned int, así que i también lo es. Mezclar int y unsigned en la condición i < n dispara avisos con -Wextra (y -Werror los convierte en error). Empezar a leer los prototipos y respetar los tipos exactos es parte del ejercicio.

ex02ft_str_is_alpha

Prototipo: int ft_str_is_alpha(char *str)Cadena vacía → 1

Devolver 1 si str contiene solo caracteres alfabéticos (y también para la cadena vacía), 0 si aparece cualquier otra cosa.

int	ft_str_is_alpha(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		if (str[i] < 'A' || (str[i] > 'Z' && str[i] < 'a') || str[i] > 'z')
			return (0);
		i++;
	}
	return (1);
}

La condición niega la pertenencia a los dos rangos de letras: A–Z (65–90) y a–z (97–122). Un carácter no es alfabético si está por debajo de 'A', en el hueco entre 'Z' y 'a' (donde viven [, \, ]...), o por encima de 'z'. La cadena vacía nunca entra al bucle, así que devuelve 1 «gratis».

Concepto — comparar caracteres es comparar números. Escribir str[i] >= 'a' funciona porque 'a' es 97 para el compilador. Este ejercicio (y los cinco siguientes) son la versión casera de las funciones isalpha, isdigit… de <ctype.h>: predicados que responden sí/no mirando en qué tramo de ASCII cae cada byte.

ex03ft_str_is_numeric

Prototipo: int ft_str_is_numeric(char *str)Cadena vacía → 1

Igual que el anterior pero con dígitos: 1 si todo son cifras 0–9.

int	ft_str_is_numeric(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		if (str[i] < '0' || str[i] > '9')
			return (0);
		i++;
	}
	return (1);
}

Los dígitos ocupan un tramo contiguo de ASCII ('0'=48 … '9'=57), así que basta un único rango. Ojo: comprueba caracteres dígito, no el valor numérico; el signo - o un punto decimal harían devolver 0.

Concepto — el carácter '0' no vale 0. Es 48. Esa distancia de 48 entre el dígito impreso y su valor es la que se usará en C04 para convertir texto a número (str[i] - '0'). Aquí solo se valida; allí se aprovechará.

ex04ft_str_is_lowercase

Prototipo: int ft_str_is_lowercase(char *str)Cadena vacía → 1

1 si todos los caracteres son minúsculas a–z.

int	ft_str_is_lowercase(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		if (str[i] < 'a' || str[i] > 'z')
			return (0);
		i++;
	}
	return (1);
}

Un solo rango, a–z. El patrón «recorrer y rechazar al primer fallo» se repite idéntico; cambia únicamente el intervalo.

Concepto — repetición deliberada. La piscina insiste en variaciones mínimas del mismo esqueleto a propósito: se busca que el bucle-con-guardia se vuelva un reflejo, no un problema a resolver cada vez.

ex05ft_str_is_uppercase

Prototipo: int ft_str_is_uppercase(char *str)Cadena vacía → 1

1 si todos los caracteres son mayúsculas A–Z.

int	ft_str_is_uppercase(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		if (str[i] < 'A' || str[i] > 'Z')
			return (0);
		i++;
	}
	return (1);
}

Simétrico a is_lowercase, con el rango de mayúsculas.

Concepto — mayúsculas antes que minúsculas. En ASCII las mayúsculas (65–90) van antes que las minúsculas (97–122). Por eso al ordenar cadenas byte a byte "Zoo" queda antes que "abeja": es la lógica que gobernará ft_strcmp en C03.

ex06ft_str_is_printable

Prototipo: int ft_str_is_printable(char *str)Cadena vacía → 1

1 si todos los caracteres son imprimibles.

int	ft_str_is_printable(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		if (str[i] < 32 || str[i] > 126)
			return (0);
		i++;
	}
	return (1);
}

El rango imprimible de ASCII va del espacio (32) a la tilde ~ (126). Por debajo de 32 están los caracteres de control (tabulador = 9, salto de línea = 10…), que existen pero no «se ven».

Concepto — hay bytes que no se ven. Esta frontera 32–126 es la clave de los dos últimos ejercicios del módulo: en ft_putstr_non_printable y ft_print_memory habrá que representar de otra forma los bytes que caen fuera de ella, porque enviarlos crudos a la terminal la ensuciaría o la haría pitar.

ex07ft_strupcase

Prototipo: char *ft_strupcase(char *str)Devuelve str

Pasar cada letra a mayúscula, modificando la cadena in situ.

char	*ft_strupcase(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		if (str[i] >= 'a' && str[i] <= 'z')
			str[i] = str[i] - 32;
		i++;
	}
	return (str);
}

La aritmética ASCII en acción: una minúscula está exactamente 32 posiciones por encima de su mayúscula ('a'−'A' = 97−65 = 32), así que restar 32 la convierte. Los caracteres que no son minúsculas se dejan intactos.

Concepto — modificar «en el sitio». La función no crea una copia: escribe sobre el mismo str que recibió. Esto solo es legal si quien llama pasó memoria escribible (un array, no un literal "...", que es de solo lectura). Entender la diferencia evita el segfault más habitual del módulo.

ex08ft_strlowcase

Prototipo: char *ft_strlowcase(char *str)Devuelve str

El inverso: cada letra a minúscula.

char	*ft_strlowcase(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		if (str[i] >= 'A' && str[i] <= 'Z')
			str[i] = str[i] + 32;
		i++;
	}
	return (str);
}

Ahora se suma 32 a las mayúsculas. Misma idea, signo opuesto.

Concepto — ¿por qué +32 y no una tabla?. Se podría mapear cada letra con una tabla de traducción, pero el +32 demuestra que la codificación ASCII no es arbitraria: mayúsculas y minúsculas se diseñaron separadas por una potencia de dos (32 = bit 5), justo para que cambiar la caja fuera una operación de un solo bit.

ex09ft_strcapitalize

Prototipo: char *ft_strcapitalize(char *str)Devuelve str

Poner en mayúscula la primera letra de cada palabra y el resto en minúscula. Una «palabra» es una secuencia de caracteres alfanuméricos.

static int	ft_is_alnum(char c)
{
	if (c >= '0' && c <= '9')
		return (1);
	if (c >= 'a' && c <= 'z')
		return (1);
	if (c >= 'A' && c <= 'Z')
		return (1);
	return (0);
}

char	*ft_strcapitalize(char *str)
{
	int	i;

	i = 0;
	while (str[i])
	{
		if (i != 0 && ft_is_alnum(str[i - 1]))
		{
			if (str[i] >= 'A' && str[i] <= 'Z')
				str[i] = str[i] + 32;
		}
		else if (str[i] >= 'a' && str[i] <= 'z')
			str[i] = str[i] - 32;
		i++;
	}
	return (str);
}

La clave es detectar el inicio de palabra: un carácter empieza palabra si es el primero de la cadena o si el anterior no es alfanumérico. En ese caso se fuerza a mayúscula; en cualquier otro, a minúscula. Con la entrada 42mots, el 4 abre palabra pero no es letra (queda igual), y la m ya no es inicio (el 2 anterior es alfanumérico), así que se queda minúscula: 42mots. El helper ft_is_alnum se declara static porque no forma parte de la entrega.

Concepto — el estado está en el vecino. Aquí ya no basta con mirar el carácter actual: la decisión depende del contexto (qué había justo antes). Es el primer ejercicio del módulo con una pizca de máquina de estados, y anticipa parsers más serios donde «dónde estoy» importa tanto como «qué leo».

ex10ft_strlcpy

Prototipo: unsigned int ft_strlcpy(char *dest, char *src, unsigned int size)

La copia «segura» de BSD: copia como mucho size − 1 caracteres, siempre pone \0 (si size > 0) y devuelve la longitud de src.

unsigned int	ft_strlcpy(char *dest, char *src, unsigned int size)
{
	unsigned int	i;
	unsigned int	len;

	len = 0;
	while (src[len])
		len++;
	i = 0;
	while (i + 1 < size && src[i])
	{
		dest[i] = src[i];
		i++;
	}
	if (size > 0)
		dest[i] = '\0';
	return (len);
}

Primero se mide src completo (ese es el valor a devolver, pase lo que pase con la copia). Luego se copia dejando siempre un hueco para el terminador: la guarda i + 1 < size reserva la última posición. Devolver la longitud real de src —aunque no quepa— es lo que permite a quien llama detectar que hubo truncamiento (retorno >= size).

Concepto — desbordamientos de búfer. strcpy no conoce el tamaño del destino: si src es más largo, escribe fuera y corrompe memoria (la base de incontables vulnerabilidades). strlcpy nació para eso: recibe size y nunca lo excede. Reimplementarla es tomar contacto con la seguridad de memoria, tema que atraviesa todo C.

ex11ft_putstr_non_printable

Prototipo: void ft_putstr_non_printable(char *str)Autorizada: write

Imprimir la cadena, pero mostrando los caracteres no imprimibles como \ seguido de su código hexadecimal en minúsculas y dos dígitos. Así, un salto de línea (0x0a) se ve como \0a.

void	ft_putstr_non_printable(char *str)
{
	char	*hex;
	int		i;

	hex = "0123456789abcdef";
	i = 0;
	while (str[i])
	{
		if (str[i] >= 32 && str[i] <= 126)
			write(1, &str[i], 1);
		else
		{
			write(1, "\\", 1);
			write(1, &hex[(unsigned char)str[i] / 16], 1);
			write(1, &hex[(unsigned char)str[i] % 16], 1);
		}
		i++;
	}
}

Para convertir un byte a hexadecimal se parte en dos «nibbles» de 4 bits: la cifra alta es byte / 16 y la baja byte % 16, y cada una indexa la tabla "0123456789abcdef". El (unsigned char) es crucial: sin él, un byte con el bit alto puesto (valor > 127) se interpretaría como char negativo y las divisiones darían índices negativos.

Concepto — hexadecimal como lenguaje de bytes. Un byte son 8 bits = dos dígitos hex exactos (00–ff). Por eso los volcados de memoria, los colores web y los hashes se escriben en hex: es la notación más compacta que mapea limpiamente cada mitad de un byte. Este ejercicio es el ensayo general del siguiente.

ex12ft_print_memory

Prototipo: void *ft_print_memory(void *addr, unsigned int size)Autorizada: write

Volcar una región de memoria en tres columnas, al estilo de un editor hexadecimal: la dirección en hex, el contenido en hex (agrupado de dos en dos bytes, relleno con espacios si la línea queda a medias) y el contenido como texto (los no imprimibles se sustituyen por .). Dieciséis bytes por línea; si size es 0 no se imprime nada. Devuelve addr.

$> ./ft_print_memory
000000010a161f40: 426f 6e6a 6f75 7220 6c65 7320 616d 696e Bonjour les amin
000000010a161f50: 6368 6573 090a 0963 0720 6573 7420 666f ches...c. est fo
...

La función se reparte en tres ayudantes static (dirección, columna hex, columna texto) más el bucle principal, que avanza de 16 en 16 bytes. El núcleo es la columna hex, que decide en cada posición si hay byte que imprimir o hay que rellenar con espacios para que la columna de texto quede siempre alineada:

static void	ft_hexline(unsigned char *p, unsigned int start, unsigned int size)
{
	char	*h;
	int		j;

	h = "0123456789abcdef";
	j = 0;
	while (j < 16)
	{
		if (start + j < size)
		{
			write(1, &h[p[start + j] / 16], 1);
			write(1, &h[p[start + j] % 16], 1);
		}
		else
			write(1, "  ", 2);
		if (j % 2 == 1)
			write(1, " ", 1);
		j++;
	}
}

El if (j % 2 == 1) mete un espacio tras cada dos bytes, y el else con dos espacios rellena las posiciones que ya no existen en la última línea: así, aunque la fila esté incompleta, la columna de texto arranca siempre en la misma columna. La dirección se imprime con un bucle que extrae los 16 dígitos hex de un unsigned long, y la columna de texto reusa la frontera 32–126 de ft_str_is_printable.

Concepto — la memoria es un array de bytes, y punto. Un void * es «una dirección, sin tipo». Al castearlo a unsigned char * le decimos al compilador «trátalo como bytes crudos» y podemos recorrerlo como cualquier array. Esto es literalmente lo que hacen gdb, xxd o un depurador: no hay variables ni tipos ahí abajo, solo bytes en direcciones consecutivas. Ver una struct o un int «desnudos» en hex es el momento en que la memoria deja de ser abstracta.
