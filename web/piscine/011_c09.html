C Piscine — C 09

El módulo de la compilación. Aquí se deja de compilar a mano: se crea una librería estática (libft.a) y se automatiza su construcción con un Makefile. Se aprende qué hace el enlazador y por qué existe make. 3 ejercicios (ex00–ex02).

  • ex00 — libft
  • ex01 — Makefile
  • ex02 — ft_split
La introducción — El enunciado cita un fragmento de Proyecto Hail Mary de Andy Weir: un profesor humano y un alienígena (un "eridiano") intentan construir un vocabulario común a base de gestos, empezando por "sí" y "no" y liándose enseguida. ex00libft

Entregables: libft_creator.sh + 5 .cFunciones: write

Crear la biblioteca libft.a con cinco funciones (ft_putchar, ft_swap, ft_putstr, ft_strlen, ft_strcmp) y un script que la construya:

#!/bin/sh
cc -Wall -Wextra -Werror -c ft_putchar.c ft_swap.c ft_putstr.c ft_strlen.c \
	ft_strcmp.c
ar rcs libft.a ft_putchar.o ft_swap.o ft_putstr.o ft_strlen.o ft_strcmp.o

El cc -c compila cada .c a un objeto .o (código máquina, pero sin enlazar). El ar rcs empaqueta esos objetos en un solo archivo libft.a.

Qué es una librería estática — Compilar un programa tiene dos fases: compilar (cada .c → un .o con el código de sus funciones) y enlazar (juntar los .o y resolver quién llama a quién). Una librería .a es, literalmente, un archivo (eso es ar, de archiver, el mismo linaje que tar) que agrupa varios .o para no ir pasándolos sueltos. La s de rcs escribe un índice de símbolos para que el enlazador encuentre rápido cada función. "Estática" quiere decir que, al enlazar, el código de las funciones que uses se copia dentro de tu ejecutable (frente a las dinámicas .so, que se cargan aparte al arrancar). Es el primer paso para dejar de reescribir ft_strlen en cada proyecto.

ex01Makefile

Entregable: MakefileReglas: all, clean, fclean, re

El mismo resultado que el script, pero con un Makefile: busca las fuentes en srcs/, la cabecera en includes/, compila con -Wall -Wextra -Werror y crea libft.a. Sin recompilar de más, sin wildcards.

NAME = libft.a
CC = cc
CFLAGS = -Wall -Wextra -Werror
INCLUDES = -I includes
SRCS = srcs/ft_putchar.c srcs/ft_swap.c srcs/ft_putstr.c \
       srcs/ft_strlen.c srcs/ft_strcmp.c
OBJS = $(SRCS:.c=.o)

all: $(NAME)

$(NAME): $(OBJS)
	ar rcs $(NAME) $(OBJS)

%.o: %.c
	$(CC) $(CFLAGS) $(INCLUDES) -c $< -o $@

clean:
	rm -f $(OBJS)

fclean: clean
	rm -f $(NAME)

re: fclean all

.PHONY: all clean fclean re
Por qué existe make y su grafo de dependencias — El script del ejercicio anterior recompila todo cada vez. En un proyecto grande eso es insoportable. make resuelve el problema con un grafo de dependencias: cada objetivo (libft.a) depende de unos prerequisitos (los .o), y cada .o depende de su .c. Antes de rehacer algo, make compara las fechas de modificación: si el .c no ha cambiado desde que se generó el .o, no lo recompila. Por eso al tocar un solo fuente solo se recompila ese, y volver a ejecutar make sin cambios responde "nothing to be done". Las reglas clean (borra los .o), fclean (borra también la librería) y re (todo de cero) son la convención de 42. La regla %.o: %.c es un patrón: "para hacer cualquier .o, compila su .c", con $< = el prerequisito y $@ = el objetivo. Y el aviso "cuidado con los wildcards": listar las fuentes a mano en vez de *.c evita que un archivo de sobra se cuele en la compilación.

ex02ft_split

Entregable: ft_split.cFunciones: malloc

Partir una cadena en trozos usando cualquier carácter de un charset como separador, y devolver un array de cadenas terminado en NULL. Sin trozos vacíos.

char	**ft_split(char *str, char *charset);

La solución se descompone en piezas pequeñas (Norma: máximo 25 líneas por función): detectar si un carácter es separador, contar cuántas palabras hay, duplicar una palabra reservando su tamaño exacto, y rellenar el array. Se reserva sitio para nº palabras + 1 y la última entrada se pone a NULL como centinela.

El clásico que lo junta todo — ft_split es el ejercicio donde convergen casi todos los conceptos previos: punteros a puntero (char **, un array de cadenas), memoria dinámica (un malloc para el array y uno por cada palabra), recorrer cadenas con centinela, y descomponer un problema en funciones cortas para respetar la Norma. La regla "sin cadenas vacías" obliga a pensar los casos borde: separadores al principio, al final, o varios seguidos ("saca las conclusiones pertinentes", dice el enunciado con retranca). Contar primero y reservar exacto — en vez de ir agrandando el array — es el patrón de dos pasadas que evita realloc y fugas.
