C Piscine — C 00

Primer módulo de C. Una sola función autorizada en todo el módulo: write. Nueve ejercicios que van de imprimir un carácter a generar combinatorias con recursión — todo construido desde un único byte.

  • ex00 — ft_putchar
  • ex01 — ft_print_alphabet
  • ex02 — ft_print_reverse_alphabet
  • ex03 — ft_print_numbers
  • ex04 — ft_is_negative
  • ex05 — ft_print_comb
  • ex06 — ft_print_comb2
  • ex07 — ft_putnbr
  • ex08 — ft_print_combn
Por qué solo write — Es la decisión pedagógica que define el módulo. printf es una función gigante de la librería estándar que formatea, bufferea y esconde todo lo interesante. write(fd, buf, n) es la llamada al sistema desnuda: "kernel, escribe estos n bytes de esta dirección en este descriptor". Quitándote printf, 42 te obliga a descubrir que todo lo demás se construye: imprimir un número, un alfabeto o una tabla es siempre, al final, empujar bytes uno a uno por el descriptor 1 (stdout). Cuando en C04 reimplementes putnbr y en el cursus escribas tu propio printf, este será el único ladrillo de base. (El prólogo del enunciado — la "mermelada de fideos" de Pierre Dac, humorista francés — es puro absurdo intencional: dos páginas de receta imposible que terminan en "C sí que vale la pena".)

ex00ft_putchar

Entrega: ft_putchar.cAutorizado: write
void	ft_putchar(char c)
{
	write(1, &c, 1);
}

El enunciado incluso da la línea. Lo que se evalúa es entender sus tres argumentos: descriptor 1 (stdout), la dirección del carácter (&c — write no recibe valores, recibe punteros a memoria) y la longitud en bytes.

Qué te obliga a aprender — Tu primer contacto con dos ideas que lo atraviesan todo: (1) las funciones del sistema trabajan con direcciones de memoria, no con valores — de ahí el &; y (2) un char no es "una letra", es un byte, un número de 8 bits. Esta función de 1 línea es el átomo del que saldrán todas las demás salidas por pantalla de la piscine.

ex01ft_print_alphabet

Entrega: ft_print_alphabet.cAutorizado: write
void	ft_print_alphabet(void)
{
	char	c;

	c = 'a';
	while (c <= 'z')
	{
		write(1, &c, 1);
		c++;
	}
}
Qué te obliga a aprender — Que los caracteres son números y se puede hacer aritmética con ellos: 'a' vale 97 en ASCII y 'a' + 1 es 'b'. Ese diseño — heredar del telégrafo una tabla donde las letras son consecutivas — es lo que permite recorrer el alfabeto con un contador. También es tu primer bucle while de la Norma: 42 prohíbe for precisamente para que veas las tres piezas del bucle (inicialización, condición, avance) por separado.

ex02ft_print_reverse_alphabet

Entrega: ft_print_reverse_alphabet.cAutorizado: write
	c = 'z';
	while (c >= 'a')
	{
		write(1, &c, 1);
		c--;
	}
Qué te obliga a aprender — Parece el mismo ejercicio y esa es la trampa: al invertir el sentido cambian tres cosas coordinadas (valor inicial, condición de parada, operador de avance). El error clásico del principiante es cambiar dos de las tres. Enseña a razonar el bucle como un invariante y no como una receta copiada.

ex03ft_print_numbers

Entrega: ft_print_numbers.cAutorizado: write
	c = '0';
	while (c <= '9')
	{
		write(1, &c, 1);
		c++;
	}
Qué te obliga a aprender — La diferencia entre el número 0 y el carácter '0' (que vale 48 en ASCII). Confundirlos es uno de los errores más comunes de todo C. La conversión digito + '0' ↔ caracter - '0' que aquí se insinúa será la pieza central de putnbr (ex07) y de atoi (C04).

ex04ft_is_negative

Entrega: ft_is_negative.cAutorizado: write
void	ft_is_negative(int n)
{
	if (n < 0)
		write(1, "N", 1);
	else
		write(1, "P", 1);
}
Qué te obliga a aprender — Dos cosas pequeñas pero deliberadas: (1) leer la especificación con lupa — el 0 es "P", y quien imprime "N" para el cero suspende: los contratos se cumplen al pie de la letra, como hará la Moulinette; y (2) que un literal de cadena "N" ya es una dirección de memoria válida para write — la primera pista de que las cadenas en C son punteros.

ex05ft_print_comb

Entrega: ft_print_comb.cAutorizado: write

Todas las combinaciones de tres dígitos distintos en orden creciente: 012, 013, …, 789.

	a = '0';
	while (a <= '7')
	{
		b = a + 1;
		while (b <= '8')
		{
			c = b + 1;
			while (c <= '9')
			{
				ft_print_trio(a, b, c);
				c++;
			}
			b++;
		}
		a++;
	}
Qué te obliga a aprender — Dos ideas de peso. Primera: generar por construcción, no filtrar. La solución ingenua enumera 000–999 y descarta; la buena hace que cada bucle empiece donde el anterior lo dejó (b = a + 1), de modo que solo se generan combinaciones válidas — así se piensa en combinatoria y en SQL, en backtracking, en todo. Segunda: el problema de la valla (fencepost): hay separador ", " entre elementos, no después de cada uno; detectar el último elemento (789) es la parte que de verdad se falla. Además obliga a decidir los límites de cada bucle (¿por qué a para en '7'?) razonando, no probando.

ex06ft_print_comb2

Entrega: ft_print_comb2.cAutorizado: write

Parejas de números de dos cifras: 00 01, 00 02, …, 98 99.

	s[0] = a / 10 + '0';
	s[1] = a % 10 + '0';
	s[2] = ' ';
	s[3] = b / 10 + '0';
	s[4] = b % 10 + '0';
	write(1, s, 5);
Qué te obliga a aprender — La descomposición posicional de un número: n / 10 da las decenas y n % 10 las unidades. La división entera y el módulo son las dos herramientas con las que un número "se convierte" en sus dígitos — putnbr (ex07) generaliza esto a cualquier longitud. De regalo: componer un buffer de 5 bytes y hacer un solo write enseña que la salida no tiene por qué ir carácter a carácter.

ex07ft_putnbr

Entrega: ft_putnbr.cAutorizado: write

Imprimir cualquier int, incluido -2147483648.

void	ft_putnbr(int nb)
{
	char	c;
	long	n;

	n = nb;
	if (n < 0)
	{
		write(1, "-", 1);
		n = -n;
	}
	if (n >= 10)
		ft_putnbr(n / 10);
	c = n % 10 + '0';
	write(1, &c, 1);
}
Qué te obliga a aprender — El ejercicio-emboscada del módulo, con dos lecciones. (1) Recursión por necesidad: los dígitos se obtienen del último al primero (n%10), pero se imprimen del primero al último — la pila de llamadas recursivas invierte el orden gratis. (2) Complemento a dos: en 32 bits el rango es [-2147483648, 2147483647] — asimétrico. -INT_MIN no cabe en un int: es comportamiento indefinido y el clásico segfault/valor basura de las malas soluciones. Pasar por long antes de negar es reconocer cómo representa los enteros la máquina. Es la primera vez que la piscine te castiga por no conocer los límites del hardware.

ex08ft_print_combn

Entrega: ft_print_combn.cAutorizado: write

Como ex05 pero con n dígitos (0 < n < 10).

static void	ft_rec(int *tab, int pos, int n, int start)
{
	int	d;

	if (pos == n)
	{
		ft_print_tab(tab, n);
		return ;
	}
	d = start;
	while (d <= 9)
	{
		tab[pos] = d;
		ft_rec(tab, pos + 1, n, d + 1);
		d++;
	}
}
Qué te obliga a aprender — La generalización que rompe el esquema anterior: en ex05 anidaste 3 bucles a mano, pero no puedes escribir "n bucles". La respuesta es que la recursión es un bucle de profundidad variable: cada nivel de la llamada es uno de los bucles anidados, y el array tab hace de estado compartido. Esto es backtracking en miniatura — el mismo esqueleto con el que se resuelven sudokus, n-reinas o cualquier "prueba todas las opciones válidas". Cierra el módulo conectando ex05 (enumeración por construcción) con ex07 (recursión).
