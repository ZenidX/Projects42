C Piscine — C 11

Punteros a función: pasar comportamiento como argumento. Ocho ejercicios que construyen, a mano, las piezas que en cualquier lenguaje moderno se llaman map, filter, any y sort — y un mini-intérprete de operadores resuelto con una tabla de funciones.

La idea que atraviesa el módulo — Hasta aquí una función era algo que llamabas. En C 11 una función pasa a ser un valor: se guarda en una variable, se mete en un array, se pasa como argumento. La sintaxis void (*f)(int) se lee «puntero a una función que toma un int y no devuelve nada». En cuanto lo tienes, puedes escribir código que decide qué hacer sin saber cómo se hace: eso es la genericidad, y es la base de los callbacks, de qsort y de cualquier event loop.

ex00ft_foreach

Entregable: ft_foreach.cAutorizadas: ninguna

Aplicar una función a cada entero de la tabla, en orden.

void	ft_foreach(int *tab, int length, void (*f)(int))
{
	int	i;

	i = 0;
	while (i < length)
	{
		f(tab[i]);
		i++;
	}
}
Qué te obliga a aprender — Que el bucle y la acción son cosas separables. ft_foreach es el bucle; f es la acción, y llega de fuera. El mismo recorrido sirve para imprimir, para sumar o para lo que sea, sin tocar ft_foreach. Es el patrón iterador + callback en su forma más pura.

ex01ft_map

Entregable: ft_map.cAutorizadas: malloc

Como foreach, pero f devuelve un valor y se acumula todo en una tabla nueva que se retorna.

int	*ft_map(int *tab, int length, int (*f)(int))
{
	int	*res;
	int	i;

	res = malloc(sizeof(int) * length);
	if (!res)
		return (NULL);
	i = 0;
	while (i < length)
	{
		res[i] = f(tab[i]);
		i++;
	}
	return (res);
}
Qué te obliga a aprender — La diferencia entre transformar en el sitio y producir algo nuevo. map no toca la tabla original: reserva memoria y devuelve otra. Aparece aquí la responsabilidad del malloc (comprobar el NULL) y la regla implícita: quien reserva, avisa; el free lo hará quien reciba la tabla.

ex02ft_any

Entregable: ft_any.cAutorizadas: ninguna

Devuelve 1 si algún elemento hace que f devuelva algo distinto de 0. La tabla acaba en NULL.

int	ft_any(char **tab, int (*f)(char *))
{
	int	i;

	i = 0;
	while (tab[i])
	{
		if (f(tab[i]))
			return (1);
		i++;
	}
	return (0);
}
Qué te obliga a aprender — f aquí es un predicado: una función que responde sí/no sobre un elemento. Y el return (1) en cuanto encuentra uno es la evaluación en cortocircuito: no hace falta mirar el resto. Es exactamente el any() de Python o el some() de JavaScript.

ex03ft_count_if

Entregable: ft_count_if.cAutorizadas: ninguna

Cuenta cuántos elementos cumplen el predicado f.

int	ft_count_if(char **tab, int length, int (*f)(char *))
{
	int	i;
	int	count;

	i = 0;
	count = 0;
	while (i < length)
	{
		if (f(tab[i]))
			count++;
		i++;
	}
	return (count);
}
Qué te obliga a aprender — El mismo predicado de ft_any, pero ahora sin cortocircuito: hay que recorrerlo entero. Es la pareja filtrar + contar. Cambiando solo la función que pasas, la misma rutina cuenta pares, positivos o palabras que empiezan por vocal: la lógica del recuento no sabe nada del criterio.

ex04ft_is_sort

Entregable: ft_is_sort.cAutorizadas: ninguna

Devuelve 1 si la tabla está ordenada según el comparador f (negativo si el primero es menor, 0 si iguales, positivo si mayor).

int	ft_is_sort(int *tab, int length, int (*f)(int, int))
{
	int	i;
	int	up;
	int	down;

	i = 0;
	up = 1;
	down = 1;
	while (i < length - 1)
	{
		if (f(tab[i], tab[i + 1]) > 0)
			up = 0;
		if (f(tab[i], tab[i + 1]) < 0)
			down = 0;
		i++;
	}
	return (up || down);
}
Qué te obliga a aprender — Aquí f no es un predicado sino un comparador: no dice sí/no, dice «menor, igual o mayor», con el mismo convenio de signo que strcmp. Y una decisión de diseño: «ordenada» debería valer tanto para ascendente como descendente, así que llevamos dos banderas (up, down) y damos por buena la tabla si alguna se mantiene. Ese convenio de signo es el que luego usa qsort.

ex05do-op

Entregable: programa do-opAutorizadas: write

Un programa ./do-op valor1 operador valor2 que aplica + - * / %. Operador desconocido → 0; número de argumentos incorrecto → nada; división o módulo por cero → mensaje. El enunciado pide explícitamente resolverlo con una tabla de punteros a función.

typedef struct s_op
{
	char	*sym;
	int		(*f)(int, int);
}	t_op;

/* ... se rellena ops[] con {"+", &ft_add}, {"-", &ft_sub}, ... */
while (i < 5)
{
	if (!ft_strcmp(ops[i].sym, op))
		return (ops[i].f(a, b));
	i++;
}
return (0);   /* operador desconocido: el resultado es 0 */

Dos trampas del enunciado, visibles en sus ejemplos:

  • Parsing tolerante: ./do-op 42amis - --+-20toto12 da 62. El ft_atoi tiene que saltarse el sufijo basura (amis), contar varios signos seguidos (--+- = negativo) y parar en la primera no-cifra: --+-20toto12 vale -20, y 42 - (-20) = 62.
  • Dividir por cero antes de dividir: no se puede llamar a ft_div(a, 0) y capturar el error después — eso es un SIGFPE. Hay que interceptarlo antes y escribir Stop : division by zero.
Qué te obliga a aprender — Que una tabla de punteros a función es un dispatcher: sustituye una escalera de if/else por una búsqueda en datos. Añadir un operador es añadir una fila, no tocar la lógica. Así funcionan por dentro los intérpretes, las máquinas virtuales y las tablas de syscalls del kernel. La Norma, además, empuja a trocearlo en ficheros (máx. 5 funciones cada uno) con un Makefile que los enlaza.

ex06ft_sort_string_tab

Entregable: ft_sort_string_tab.cAutorizadas: ninguna

Ordena por código ASCII un array de cadenas terminado en NULL, intercambiando los punteros de la tabla (nunca copiando las cadenas).

if (ft_strcmp(tab[i], tab[i + 1]) > 0)
{
	tmp = tab[i];
	tab[i] = tab[i + 1];
	tab[i + 1] = tmp;
	i = 0;
}
Qué te obliga a aprender — Que ordenar no es mover datos, es mover referencias. Las cadenas se quedan donde están en memoria; lo único que baraja el algoritmo son los punteros del array. Intercambiar tres char * es barato; copiar cadenas enteras sería caro e innecesario. Es la misma razón por la que se ordenan índices o punteros, no registros completos.

ex07ft_advanced_sort_string_tab

Entregable: ft_advanced_sort_string_tab.cAutorizadas: ninguna

Igual que el anterior, pero el criterio de orden llega como parámetro. Pasándole ft_strcmp se obtiene el mismo resultado que ft_sort_string_tab.

void	ft_advanced_sort_string_tab(char **tab, int (*cmp)(char *, char *))
{
	/* ... mismo bucle, pero comparando con cmp(tab[i], tab[i + 1]) ... */
}
Qué te obliga a aprender — El paso final de la abstracción: sacar el criterio fuera del algoritmo. El mismo ordenador sirve para orden ASCII, por longitud o inverso; solo cambia la función que le pasas. Esto es, literalmente, la firma de qsort de la librería estándar: void qsort(void *, size_t, size_t, int (*)(const void *, const void *)). Acabas de reinventarla.
