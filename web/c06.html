C Piscine — C 06

El módulo más corto: cuatro ejercicios, y todos son programas con su propia función main. El tema es uno solo — los argumentos de la línea de comandos: qué son argc y argv, de dónde salen y qué puedes hacer con ellos.

  • ex00 — ft_print_program_name
  • ex01 — ft_print_params
  • ex02 — ft_rev_params
  • ex03 — ft_sort_params
El concepto que vertebra el módulo: quién llama a tu main — Hasta ahora escribías funciones que evaluaba un tester. Aquí escribes programas, y un programa en C empieza en main… pero main no se ejecuta solo: lo llama el sistema operativo cuando tecleas ./a.out uno dos tres. Y le pasa dos argumentos igual que tú se los pasas a cualquier función: int main(int argc, char **argv). argc (argument count) es cuántas palabras había en la línea, contando el propio nombre del programa. argv (argument vector) es un array de cadenas con esas palabras: argv[0] es siempre el nombre con el que se invocó el programa, argv[1] el primer argumento real, y así hasta argv[argc-1]; por convención argv[argc] es NULL. No hay magia: es el mismo shell que trabajaste en Shell 00/01 el que trocea tu línea por espacios y te la entrega. Todo ls -la, grep patrón fichero o cc -Wall main.c que has escrito llega a su main exactamente así. Este módulo es donde por fin ves el otro lado del mostrador. (El prólogo reproduce la escena de los bolos de El Gran Lebowski, con Walter gritando "¡apunta un cero!"; puro relleno marca de la casa.)

ex00ft_print_program_name

Entrega: ft_print_program_name.cAutorizado: write

Imprimir el nombre del programa (el propio ./a.out) seguido de un salto de línea.

int	main(int argc, char **argv)
{
	int	i;

	(void)argc;
	i = 0;
	while (argv[0][i])
	{
		write(1, &argv[0][i], 1);
		i++;
	}
	write(1, "\n", 1);
	return (0);
}

El nombre está en argv[0], que es una cadena como cualquier otra: se recorre carácter a carácter hasta el '\0'. El (void)argc; es necesario porque compilamos con -Wextra -Werror y no usar un parámetro es un aviso que aquí se convierte en error; "tocarlo" con el cast a void le dice al compilador "sé que existe y lo ignoro a propósito".

Qué te obliga a aprender — Que argv[0] no es un extra: es el primer elemento y siempre está. De ahí sale el idioma Unix de que un mismo binario se comporte distinto según con qué nombre lo llames (un enlace simbólico con otro nombre y un if sobre argv[0]). Y aprendes a lidiar con -Werror sin trampas: el cast a void es la forma limpia y estándar de silenciar un parámetro no usado.

ex01ft_print_params

Entrega: ft_print_params.cAutorizado: write

Imprimir cada argumento en su propia línea, en orden, saltándose argv[0].

int	main(int argc, char **argv)
{
	int	i;

	i = 1;
	while (i < argc)
	{
		print_str(argv[i]);
		i++;
	}
	return (0);
}

El bucle empieza en i = 1 para saltar el nombre del programa y llega hasta argc - 1. print_str es un pequeño helper static que escribe una cadena y su salto de línea (mismo patrón de recorrer hasta el '\0').

Qué te obliga a aprender — La estructura real de argv: un char **, es decir, un array de punteros a cadenas. argv[i] es una cadena completa; argv[i][j] es un carácter suelto. Recorrer argv con un índice acotado por argc es el modelo mental que necesitarás para cualquier programa de línea de comandos, incluidos los que parsean opciones y flags.

ex02ft_rev_params

Entrega: ft_rev_params.cAutorizado: write

Lo mismo que ex01 pero en orden inverso: del último argumento al primero (sin argv[0]).

int	main(int argc, char **argv)
{
	int	i;

	i = argc - 1;
	while (i >= 1)
	{
		print_str(argv[i]);
		i--;
	}
	return (0);
}

El único cambio respecto a ex01 es la dirección del recorrido: se arranca en argc - 1 (el último) y se baja hasta 1.

Qué te obliga a aprender — Que recorrer una colección de atrás hacia delante es solo cuestión de invertir el índice y la condición, no de tocar los datos. No hace falta mover ni copiar nada en argv: cambiamos cómo lo leemos. Es la misma idea que verás al invertir una cadena o una lista, pero sin escribir en memoria.

ex03ft_sort_params

Entrega: ft_sort_params.cAutorizado: write

Imprimir los argumentos (sin argv[0]) ordenados según el orden ASCII, uno por línea.

static int	ft_strcmp(char *a, char *b)
{
	int	i;

	i = 0;
	while (a[i] && a[i] == b[i])
		i++;
	return ((unsigned char)a[i] - (unsigned char)b[i]);
}

static void	sort(char **tab, int size)
{
	char	*tmp;
	int		i;

	i = 1;
	while (i < size)
	{
		if (ft_strcmp(tab[i - 1], tab[i]) > 0)
		{
			tmp = tab[i - 1];
			tab[i - 1] = tab[i];
			tab[i] = tmp;
			i = 1;
		}
		else
			i++;
	}
}

Ordenar cadenas necesita saber cuál va "antes": eso lo decide ft_strcmp, que compara carácter a carácter y devuelve la diferencia en el primer punto donde difieren. Y ordenar necesita mover: pero lo que se intercambia no son las cadenas sino los punteros del array tab (por eso tmp es un char *). El algoritmo es un gnome sort, el mismo de C01: si el par está desordenado lo intercambia y reinicia; si no, avanza.

Qué te obliga a aprender — Dos ideas grandes. (1) Comparar cadenas no es comparar con == (eso compararía direcciones, no contenido): hay que recorrerlas, y el cast a unsigned char asegura que el orden de bytes altos sea el correcto — así se comporta el strcmp real. (2) Ordenar un array de punteros mueve las referencias, no los datos: barato y sin tocar las cadenas originales, que además no debes modificar. Aquí se juntan todo lo del módulo (recorrer argv) con lo de C01 (punteros, swap, sort) — por eso es el cierre natural de C06.
