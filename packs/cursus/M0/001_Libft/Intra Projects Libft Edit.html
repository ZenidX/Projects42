    Introduction
    

    
Al evaluar un proyecto, por favor sigue estas reglas esenciales para garantizar la equidad y
    mantener un entorno de aprendizaje positivo:

    1. **Mantén el respeto y sé una persona constructiva**
    - Mantén una actitud educada, cordial y respetuosa durante todo el proceso de
      evaluación. El bienestar de la comunidad depende de ello.
    - Las evaluaciones constructivas ayudan a las personas a crecer y a mejorar.
      El bienestar de la comunidad depende de ello.

    2. **Identifica y discute las discrepancias**
    - Trabaja con la persona evaluada o con el grupo evaluado los posibles fallos de funcionalidad del proyecto.
      Tómate el tiempo de debatir y comentar cualquier incidencia que detectes.

    3. **Reconoce distintos enfoques**
    - Ten en cuenta que diferentes estudiantes pueden interpretar de manera distinta las 
      instrucciones y requisitos del proyecto.
    - Mantén la mente abierta y evalúa de la manera más honesta y rigurosa posible.
    - La efectividad de la evaluación entre pares depende de un análisis serio y reflexivo.

    4. **Manejo de ejercicios incorrectos**
    - Si encuentras un ejercicio incorrecto, detén la evaluación inmediatamente.
    - No pases al siguiente ejercicio si uno previo es incorrecto.
    - Utiliza las banderas (flags) apropiadas para reportar el problema y coméntalo con la persona evaluada.
    

    

    

    

    Guidelines
    

    
- Evalúa solo el trabajo entregado en el repositorio de Git de la persona o grupo evaluado.
    - Verifica varias veces que el repositorio Git entregado realmente pertenezca a la persona
      o grupo evaluado. Asegúrate de que se trata del proyecto correcto y de que 'git clone'
      se realiza en una carpeta vacía.
    - Comprueba que no existan alias maliciosos que se puedan utilizar para
      engañarte y hacerte evaluar algo que no pertenece al repositorio real.
    - Para evitar sorpresas, y si procede, revisad en conjunto cualquier programa
      utilizado para facilitar la evaluación (programa de prueba o automatización).
    - No confíes a ciegas en estos programas; podrían fallar o ser incorrectos.
    - Verifica que el Makefile no contenga 'wildcards' y que no vuelva a enlazar los objetos.
      Si eso ocurriera, la nota final sería un 0.
    - Utiliza 'make', y luego 'make --debug' para asegurarte.
    - Si no has completado el proyecto que vas a evaluar, debes leer el enunciado
      completo antes de empezar la evaluación.
    - Utiliza las banderas disponibles al final de la evaluación para reportar los
      distintos casos según corresponda (repositorio vacío, programa no funcional,
      fallos de Norma, trampas, etc). En estos casos, el proceso de evaluación
      finaliza y la nota final es un 0, o -42 en caso de trampas.
      Excepto en casos de trampas, se recomienda continuar la evaluación para identificar
      otros fallos y evitar que se repitan en el futuro.
    - El único archivo que deberías modificar es el de configuración, si existe.
      Si necesitas editar otro archivo, explica los motivos a la persona evaluada
      y asegúrate de que ambas partes estéis de acuerdo antes de modificar nada.
    - Debes verificar la ausencia de fugas de memoria. Toda la memoria reservada en
      la pila ('heap') debe liberarse correctamente antes del fin de ejecución. Puedes
      utilizar cualquiera de las diferentes herramientas para verificar esto, como 'leaks',
      'valgrind' o 'e_fence'. En caso de fugas de memoria, utiliza la bandera adecuada
      al final de la evaluación.

    Preliminares
    

    Si se sospecha que el trabajo entregado no pertenece a la persona o
personas evaluadas, la evaluación se detiene por completo y debes reportar el caso
utilizando la opción 'Cheat' al final de la evaluación.
Por favor, toma esta decisión con calma, sabiamente y de forma justa.
Utiliza esta opción con precaución.

    

    

    Pruebas preliminares
    

    

      

    • The review is done in the presence of the evaluated learner. This
is how everyone progresses: by interacting with others.
If the evaluated learner is not present, they must be marked as absent,
and the defense will not take place.
      • 

    • If no work has been submitted or if files, directories, or filenames are incorrect,
use the flag "Empty Work" to report it and the grade will be automatically set to 0.
The evaluation process ends immediately.
      • 

    • For this project, the evaluator must clone the student's Git repository.
      • 

    • Check the project with the Norminette. If the Norminette check fails,
use the flag "Norme error" to report it and the grade will be automatically
set to 0. The evaluation process ends immediately.
      • 

    • Check for the presence of global variables. If any are found, the grade is 0.
      •

    Archivo README
    

    

    ¿El repositorio contiene un archivo README.md en su directorio raíz, e incluye todos los siguientes elementos?
    


      

    • La primera línea está en cursiva y tiene exactamente el formato: This project has been created as part of the 42 curriculum by <login1>[, <login2>[, <login3>[...]]].
      • 

    • Una sección "Descripción" que explique el propósito del proyecto y ofrezca una breve visión general.
      • 

    • Una sección "Instrucciones" con información relevante sobre la compilación, instalación y/o ejecución.
      • 

    • Una sección "Recursos" que enumere las referencias (documentación, tutoriales, etc.) e indique cómo se ha utilizado la inteligencia artificial, especificando para qué tareas y en qué partes del proyecto.
      • 

    • Una descripción detallada de la biblioteca creada para el proyecto.
      • 

    


    Si falta alguno de los elementos requeridos, la nota será 0.
